# 战前巡视与开战回归

运行 `./Tests/BattleStartup/Run.ps1`（.NET 8，无额外 NuGet 依赖）。
测试直接编译生产的 `BattleManager.Startup.cs`，用可逐步推进的协程调度替身和镜头/UI 记录器验证：
重复开战/巡视、开始前跳过、巡视中跳过、自然结束与连点、空敌人列表、列表变化、教程重复完成、
初始化前开战请求、UI/事件重入、禁用/退出、旧流程跨初始化和跨场景干扰。
停止后的协程还会被强制继续推进，验证版本检查能挡住迟到操作。

完整项目的初始化、真实 Unity 协程调度、Cinemachine 和场景切换需另做 Unity 场景验收。
初始化由测试夹具提供，生产初始化与 GM/教程调用关系通过完整项目编译检查。

## 处理方式

- 原代码用 Tween 预估总巡视时长，另用协程逐个巡视；重复 StartBattle 只停止 Tween，
  旧协程继续运行并失去句柄。现改为单个协程涵盖启动等待和巡视，完成后直接进入战斗。
- Ready -> Sweeping -> Introduction -> Active 只推进一次；跳过不依赖句柄非空。
- 每次取消/重置推进流程版本；协程每次切镜头、等待后和进入战斗前均检查当前版本。
- 同一轮初始化与 StartBattle 防止重复和事件重入。初始化前的开战请求保留到初始化完成。
- 场景禁用、胜负和退出取消巡视。旧场景只能操作自己拥有的跳过按钮。
- 教程完成通过 CompleteBattleIntroduction 统一进入，防止重复对话和重复 PlayerStart。
- GM 的调试延迟捕获原管理器与场景，不再通过延迟执行时的单例影响新场景。

## Unity 场景验收

1. 正常进入一个多敌人场景，在第一次/中途/最后一次巡视点击跳过，连点也只进入一次。
2. 分别对有教程、已看教程、没有激活敌人的场景验证自然结束与跳过。
3. 开战过程快速退出或重新加载，确认旧巡视不改变新场景镜头/按钮。
4. 在巡视中人工再次调用 StartBattle/SweepActiveEnemies，确认无第二轮巡视，回合数仅为 1。

场景和预制体的事件绑定保持原接口，不需要手动改配置。
