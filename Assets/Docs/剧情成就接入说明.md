# 剧情 Steam 成就

## Steam 后台配置

在本游戏 App ID 的「统计与成就」中创建并发布：

| API Name | 建议显示名 | 触发条件 |
| --- | --- | --- |
| `ACH_GAMEOVER` | 死亡结局 | 剧情执行 `ACH(ACH_GAMEOVER)` |

API Name 区分大小写，必须与代码/剧情表一致。这里只实现了客户端，后台成就仍需创建并发布。

## 剧情指令

所有成就统一使用独立指令，参数为 Steam 后台的 API Name：

```text
ACH(成就API名)
```

需要在死亡结局或章节结束时触发成就，可使用 `+` 拼接，成就指令放在结束指令之前：

```text
ACH(ACH_GAMEOVER)+GAMEOVER
ACH(ACH_CHAPTER_1)+END(任务名,进度)
```

- `GAMEOVER` 本身不触发成就。
- `END(任务名,进度)` 只保存任务进度并结束剧情，不触发成就。旧写法的第三项不再触发成就，请改用独立 ACH 指令。
- ACH 只接受一个非空 API Name；空参数或多个参数会报格式错误，不提交成就。
- `ACH_CHAPTER_1` 只是示例，使用前需在 Steam 后台创建对应成就。
- 只在需要发成就的剧情行添加 ACH，不会根据章节编号自动解锁。
- 原有 `+` 拼接指令方式保留。
- ACH 参数中的成就名不会被当作 CHAPTER、GAMEOVER 等其他指令执行。

## 运行与验证

不需要手动挂载新的组件。首次触发成就时自动创建跨场景的 `SteamAchievements`，复用现有 `SteamManager` 完成初始化和回调处理。

1. 启动 Steam，登录拥有当前 App ID 访问权限的账号。
2. 确保 `steam_appid.txt` 正确，且后台 `ACH_GAMEOVER` 已发布。
3. 在需要测试的剧情行填写 `ACH(ACH_GAMEOVER)+GAMEOVER`，运行游戏至该行。
4. Console 中应先出现 `[SteamAchievements] 等待提交成就：ACH_GAMEOVER`，收到 Steam 成功回调后出现 `Steam 成就提交成功`。
5. 在 Steam 中检查该账号的成就记录；弹窗建议使用打包后的游戏验证。
6. 再次触发同一成就，本次运行中已确认的成就不会重复提交。已解锁的成就不保证再次弹窗。
7. 验证单独 END、GAMEOVER 不解锁成就，ACH 仅请求对应的成就。

提交失败/超时每 60 秒重试，等待不受游戏时间缩放影响。队列仅在本次运行中跨场景保留，不是磁盘存档；完全退出前仍未提交的请求可能丢失。Steam 初始化失败时应检查客户端和 App ID 后重新启动游戏。

## 本次验证

- 使用 Unity 2021.3.23f1 自带编译器和项目 Editor 编译参数，主脚本程序集编译通过，仅有已有代码警告。
- 通过 13 项模拟 Steam API 队列断言：空名称、名称修剪、重复触发、提交失败、回调失败、超时、错误 App ID 回调、提交期间新增成就、部分成就设置失败等。
- 未连接 Steam 后台验证真实解锁，未修改账号成就状态。
