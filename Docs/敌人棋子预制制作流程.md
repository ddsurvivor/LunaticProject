# 敌人棋子预制制作流程

更新：2026-11-01。适用 Unity 2021.3.23f1、Odin、uGUI。面向开发者，记录从现有敌人预制体制作一个新 `EnemyController` 棋子的完整流程；也可整篇作为提示词使用。关联开发计划 [B36–B39](战斗系统开发计划与验收.md#第七批新敌人与制作流程2026-11-01)。

本文以当前代码和资产为准。未在需求中给出的数值不得自行补全；需要确认的内容集中列在方尖碑示例和提示词中。

## 1. 产出物

一个敌人棋子至少包含以下内容，缺一项都不算接入完成：

| 产出 | 位置 |
| --- | --- |
| 敌人预制体 | `Assets/Prefab/Battle/Enemy/EnemyXX.prefab` |
| 棋子数据 | `Assets/ScriptableObjects/PieceDataListSO.asset` |
| 显示序列帧 | `Assets/A美术/BattleSprites/<角色>/` |
| 技能配置 | `SkillPackListSO` 或该棋子的旧内嵌技能字段 |
| 技能/护盾特效 | `Assets/A美术/VFX/`、`Assets/Anim/`、`Assets/Prefab/VFX/`、`ObjectPoolSO` |
| 场景与 AI 登记 | 战斗场景、`AIController.pieces`、按需的 `WaveController`/`FogController` |
| 验收记录 | 开发计划任务表与 `tmp/` 证据 |

## 3. 数据权威性：哪些在 SO，哪些在预制体

复制预制体后最容易出错的是“改了预制体数值但运行时被 SO 覆盖”，或“以为 SO 能配所有数值”。当前实际规则如下：

| 数据 | 配置位置 | 运行时行为 |
| --- | --- | --- |
| `pieceID` | 预制体根节点 `PieceController.pieceID` | `PlayerController.Init` 用它从 `BattleManager.pieceDataListSO` 查找 `PieceData`；重复 ID 只会取列表中第一个 |
| 名称、生命、行动力、移动范围、速度、弹药、能量、暴击/闪避、元素、掉落、被动、词条身体/标签、成长、行动条头像 | `PieceDataListSO` 的 `PieceData` | 敌人初始化时 `SetEnemyData` → `SetData` 覆盖；1 级使用基础值，再叠加 `levelGrowth` |
| 通用 `ATK`、`CON`、嘲讽值 | 预制体 `UnitAttrCenter` | `SetData` **不写**这三项；`SetEnemyData` 会把预制体值作为基础保存，再按成长增加 |
| 分类型攻击 `attackDic`、分类型护甲 `_armorDic` | `PieceDataListSO` | 只覆盖显式配置的键；未配置的键保留预制体 `UnitAttrCenter.attr` 的值 |
| 最大生命/行动力/移动/弹药/能量/暴击/闪避/元素 | `PieceDataListSO` | `SetData` 总是覆盖预制体同名值 |
| 回合速度 | `PieceData.speed`；预制体 `turnSpeedOverride` | `turnSpeedOverride > 0` 时覆盖 SO；新敌人通常置 0 |
| 等级 | 预制体 `EnemyController.level` | 默认 1；成长由 SO 的 `levelGrowth` 决定 |
| AI 策略、是否激活、导航、死亡是否保留 | 预制体 `EnemyController` | `enemyAIType`、`isActived`、`navigate`、`deadNotDelete` |
| 显示帧、精灵渲染器、阴影、高亮 | 预制体 `PieceDisplay` 与子物体 | 运行时表现数据，不在 SO |
| 血条、受击信息、Buff 图标 | 预制体中的 `EnemyCanvas` 嵌套实例 | 调世界偏移/缩放/排序，不写进 SO |
| 碰撞体、导航半径/速度/高度 | 预制体 `BoxCollider`、`NavMeshAgent` | 按体型调整；SO 不覆盖 |
| Tag/Layer | 预制体根节点 | 敌人使用 `Piece` 标签、Layer 11（以现有敌人为准） |
| 技能库、近战/远程技能 ID、初始主动技能 | `PieceDataListSO` | 设置了 `skillLibrary` 时按 ID 查库；为空时回退旧 `meleeAtk`/`rangedAtk`/`skillPacks` |
| 技能特效、弹道、动画索引、音效、MP、AI 用途 | `SkillPack` | `skillVFXType`、`bulletVFXType`、`animationIndex`、`skillSound`、`enemySkillRole` |
| 永久词条免疫 | 当前没有 `PieceData` 字段 | 现在只有战斗内 `MemeUnitState` 抗性；方尖碑的“免疫逆转敌我”需要在 B37 增加配置或专用判定 |

补充：

- 预制体上的 `_pieceData` 是 `[SerializeField] [ReadOnly]` 快照；运行时会被 `Init` 传入的 SO 数据替换。不要用修改这份快照来代替 SO 配置。
- SO 是 Odin `SerializedScriptableObject`，请在 Inspector 中编辑；直接手改 `.asset` 文本可能只改到 Unity 的 YAML 副本，实际 Odin 数据不生效。文件中同时存在 YAML 的 `pieceDataList`/`skillPacks` 副本，可能是旧的（例如 `PieceDataListSO` 的 YAML 仍显示旧内嵌攻击，而 Odin 数据已改为 `skillLibrary` + 技能 ID），不要用文本副本判断实际配置。
- 预制体 Enemy00 使用 1000，但 SO 中没有 1000 条目（复制 Enemy00 后必须改号）；SO 中的敌人编号为 1001–1009、1011、2001。新敌人分配未占用编号（1010 为空，取号前再搜索确认），不要复用。

## 4. 标准制作流程

### 4.1 选择源预制体并复制

优先复制“同阵营、同体型、没有一次性特殊死亡/召唤逻辑”的敌人。当前 `Assets/Prefab/Battle/Enemy/` 下：

| 预制体 | `pieceID` | SO 名称 | AI 基础策略 | 备注 |
| --- | --- | --- | --- | --- |
| Enemy00 | 1000 | SO 中没有 1000 条目；显示资源前缀 PC03A | 旧值 1（不在当前枚举中） | 带 `SelfHeal`，场景中仍有实例；复制后必须改为新 ID、新增 SO 条目，并清掉旧的回合事件 |
| Enemy01 | 1001 | 打印机 | 混合型 | |
| Enemy02 | 1002 | 训练无人机 | 射击型 | |
| Enemy03 | 1003 | 杜伯安 | 技能型 | |
| Enemy04 | 1004 | 军械无人机 | 混合型 | |
| Enemy05 | 1005 | 黑衣人 | 技能型 | 同阵营黑衣人，适合作为方尖碑的复制源 |
| Enemy06 | 1006 | 地效车 | 特殊型 | 非人形载具结构 |
| Enemy07/08 | 1007/1008 | 模因中毒者 1/2 | 射击型/混合型 | |
| Enemy09 | 1009 | 仲裁者 | 混合型 | |
| Enemy11 | 1011 | 自爆无人机 | 混合型 | 含自爆/死亡逻辑，除非新敌人也需要，否则不要作为源 |

操作：

1. 在 Project 窗口复制源预制体，改名 `EnemyXX`，放在 `Assets/Prefab/Battle/Enemy/`。
2. 保留根节点的核心组件：`BoxCollider`、`UnitAttrCenter`、`PieceDisplay`、`EnemyController`、`NavMeshAgent`，以及 `EnemyCanvas` 嵌套实例。
3. 保留/检查子物体：棋子精灵渲染器（`PieceDisplay.pieceSpriteRenderer`）、阴影、高亮、`EnemyCanvas`。`CardGameUI_13` 等旧装饰若不需要，删除并清理引用。
4. 复制后检查所有 `UnityEvent`：`OnInit`、`OnTurnStart`、`OnTurnEnd`、`OnHurt`、`OnDead`。源预制体上的 `SelfHeal.FullHp`、自爆、召唤等回调会跟着复制；不需要就清空，避免新敌人每回合自动满血或死亡时爆炸。
5. 复制后内部引用通常仍指向副本自身；一旦替换/重命名子物体，必须重新绑定 `pieceSpriteRenderer`、`enemyCanvas`、`unitAttrCenter`、`hightlightEffect`、`rangeUI`。

### 4.2 重绑显示资源（PieceDisplay）

`PieceDisplay` 的字段与状态对应关系：

| 字段 | 播放状态 | 说明 |
| --- | --- | --- |
| `idleSprite` | `Idle` | 循环；空列表会停在当前帧 |
| `moveSprite` | `Move` | 循环，播放速度为普通帧率的 2 倍 |
| `meleeSprites` | `Attack` | 近战普攻；`PlayAction` 在序列中点释放命中 |
| `rangeSprites` | `Shoot` | 远程普攻 |
| `dodgeSprite` | `Dodge` | 空时回退 `idleSprite`；统一播放 1 秒并带横移 |
| `hitSprite` | `Hit` | 受击一次性 |
| `deathSprites` | `Death` | 死亡一次性；结束后走掉落/回收/胜负流程 |
| `skillSpriteList` | `Skill` | 外层每个元素是一个技能组；`SkillPack.animationIndex` 选择组 |

注意事项：

- 编辑器自动加载按钮（Inspector 的“测试加载图片”）只认 `<pieceName><suffix><n>.png`，序号从 1 开始且不补零；技能帧只认 `<pieceName>skill<组>-<帧>.png`。新素材若是 `INST1idle0000.png` 这类四位补零命名，自动加载找不到，必须手工按顺序绑定，或先统一改名。
- `skillidle`、`skillover` 目前没有独立字段。若持续护盾引导需要“引导循环/结束”动画，先确认是在 `skillSpriteList` 中合并，还是扩展 `PieceDisplay`；不要假设已有字段能播放。
- 绑定后检查精灵渲染器的缩放、位置、Sorting Layer/Order、翻转和阴影；`PieceDisplay` 只负责换帧，不负责自动适配体型。
- 记录实际使用的帧数。方尖碑当前素材：idle 6 帧（0000–0005）、move 5 帧（0000–0004）、skill 12 帧（0000–0011）、skillidle 6 帧、skillover 9 帧、hit 2 帧、death 10 帧。

方尖碑的临时绑定建议（B36 可先落地，skillidle/skillover 留给 B37/B38 处理）：

- `idleSprite`：`INST1idle0000`–`INST1idle0005`
- `moveSprite`：`INST1move0000`–`INST1move0004`
- `hitSprite`：`INST1hit0000`–`INST1hit0001`
- `deathSprites`：`INST1death0000`–`INST1death0009`
- `skillSpriteList[0]`：`INST1skill0000`–`INST1skill0011`（或按技能拆成多组）
- `meleeSprites`/`rangeSprites`：无对应素材时先留空；确认普攻是否有独立表现，不要拿 skill 帧冒充普攻。

### 4.3 更新预制体数值引用

复制后逐项检查：

1. `PieceController.pieceID` 改为新 SO 条目的编号；这是运行时加载数据的唯一入口。
2. `EnemyController.level` 默认 1；`enemyAIType` 选择 [敌人策略配置](敌人策略配置.md) 中的枚举；`isActived` 按关卡初始状态；`navigate` 按是否需要导航；`deadNotDelete` 按死亡后是否保留尸体。
3. `PieceController.turnSpeedOverride` 新敌人置 0，使用 SO 的 `speed`；只有需要实例级速度覆盖时才填正数。
4. `UnitAttrCenter`：
   - 同步 `_maxHealth`、`_maxMovePoint`、`_moveRange`、`_maxAmmoCount`、`critRate`、`critDamageRate`、`elementType` 等回退值，使预制体在未 Init 时也可读；运行时仍以 SO 为准。
   - 通用 `ATK`、`CON`、`_tauntValue` 以及未在 SO 配置的分类型攻击/护甲，必须直接在这里配置；它们不会被 SO 覆盖。
   - `hpBarFill`/`hpBarUI` 若使用 `EnemyCanvas`，按现有敌人保持为空或指向 Canvas 内的组件，不要留下指向旧敌人的引用。
5. 内部引用：`pc`、`pieceDisplay`、`enemyCanvas`、`hightlightEffect`、`rangeUI` 全部指向副本自身；复制后打开 Inspector 逐个确认没有 `Missing`。
6. 体型适配：
   - `BoxCollider` 的 `size`/`center` 要覆盖实际可见范围，避免点选/遮挡异常。
   - `NavMeshAgent` 的 `radius`、`speed`、`height`、`baseOffset` 按体型调整，并在目标场景 NavMesh 上测试。
   - `EnemyCanvas` 的世界位置/缩放按新体型调整，避免血条、受击信息、Buff 图标埋进模型或飘得太高。
   - 根节点保持 `Piece` 标签、Layer 11、`isPlayerPiece = 0`。

### 4.4 在 PieceDataListSO 添加棋子数据

在 Inspector 中打开 `Assets/ScriptableObjects/PieceDataListSO.asset`，在 `pieceDataList` 添加元素：

| 字段 | 说明 |
| --- | --- |
| `pieceId` | 未占用编号；预制体 Enemy00 用 1000（SO 无该条目），SO 已有 1001–1009、1011、2001 |
| `pieceName` | 显示名，如“方尖碑” |
| `memeBodyType` | 机械/生物；方尖碑按机械无人机配置 |
| `memeTargetTags` | 如“黑衣人”；屠龙术要求目标具备该标签 |
| `maxHealth` / `maxMovePoint` / `moveRange` / `speed` | 1 级基础值 |
| `turnPortrait` / `turnPortraitIsFullBody` / `turnPortraitFraming` | 行动条头像；可留空回退立绘或棋子精灵 |
| `attackDic` | 分类型攻击力；未配置的键使用预制体 `UnitAttrCenter.attr` |
| `_armorDic` | 分类型护甲；伤害类型映射：动能=`Melee(1)`、热能=`Ranged(2)`、火种=`Electric(3)` |
| `maxAmmoCount`、`evasionRate`、`critRate`、`critDamageRate` | 战斗数值 |
| `elementType` | 元素属性 |
| `skillLibrary`、`meleeSkillId`、`rangedSkillId`、`initialSkillIds` | 统一技能库；设置后按 ID 解析，旧内嵌字段不再参与攻击解析 |
| `skillPacks`、`meleeAtk`、`rangedAtk` | 旧格式，保留兼容；当前敌人条目多数已改用 skillLibrary + 技能 ID，实际以 Inspector/Odin 数据为准 |
| `dropItemList`、`dropRate` | 掉落 |
| `passiveSkillTypes`、`attrDic`、`orderProfiles`、`innateMemeIds` | 按需 |
| `levelGrowth` | 添加条目后点“为敌人填充默认等级成长”；只补齐缺失项，不覆盖已有值 |

补充：

- `PieceData.MeleeAttack`/`RangedAttack` 在 `skillLibrary != null` 时只查技能库；如果新敌人配置了技能库却忘了填 ID，攻击会变空，不会回退旧字段。
- `levelGrowth` 的“为敌人填充默认等级成长”只是编辑器默认值，不是策划确认值；未确认成长曲线时保留为空，避免悄悄引入未批准数值。
- 方尖碑已知 1 级生命 60、护甲 热能 10/动能 5/火种 0；行动力、移动范围、速度、攻击、技能消耗、光环/护盾范围与耐久等未给，执行前向策划确认，不要自行填默认值。
- 添加条目后确认 `BattleScene.prefab` 中 `BattleManager.pieceDataListSO` 仍指向 `Assets/ScriptableObjects/PieceDataListSO.asset`。

### 4.5 配置技能、动画与特效

技能数据有两个入口，按敌体现状选择：

1. **统一技能库（优先）**：在 `SkillPackListSO` 中新增/登记 `SkillPack`，在 `PieceData` 里设置 `skillLibrary` 和 `meleeSkillId`/`rangedSkillId`/`initialSkillIds`。`skillId` 是稳定引用，发布后不要改名。
2. **旧内嵌字段**：直接在该 `PieceData` 的 `meleeAtk`/`rangedAtk`/`skillPacks` 中配置。它只为兼容旧资源保留；当前敌人条目多数已改用统一技能库，`PieceDataListSO` 的 YAML 文本副本仍可能显示旧内嵌值，不要据此判断。如果该棋子没有设置 `skillLibrary`，运行时会走这里。

每个 `SkillPack` 重点检查：

- `target`、`rangeType`、`rangeValue`、`reachKind`：目标与范围；支援/光环技能要确认目标阵营和区域类型。
- `attackPacks`、`atkTimes`、`buffPacks`、`skillEffects`：伤害、连击、附加状态/特殊效果。
- `enemySkillRole`：AI 用途（远程攻击/近战攻击/回复）；治疗和护盾技能必须标对，否则 AI 不会按预期选用。
- `mpCost`、`skillSound`、`animationIndex`：`animationIndex` 对应 `PieceDisplay.skillSpriteList` 的组下标。
- `skillVFXType`：施放位置特效；`bulletVFXType`：弹道特效；两者都必须存在于 `ObjectPoolSO`，否则运行时报“生成物体失败”。

特效制作链路：

1. 序列帧放 `Assets/A美术/VFX/`；当前 FIRESEEDbarrier 护盾素材为 `FIRESEEDbarrier0000`–`0004`（循环）和 `FIRESEEDbarrierD0000`–`0004`（破盾/消失），尚无现成 Animator Clip 和 prefab。
2. 在 `Assets/Anim/` 建 Animation Clip/Animator Controller（参考 `Heal_Fx`、`Explosion` 等现有 VFX）。
3. 在 `Assets/Prefab/VFX/` 建 VFX prefab：`SpriteRenderer` + `Animator` + `LifeTime`（参考 `Heal_Fx.prefab`），设置 Sorting Layer/Order 与生命周期。
4. 在 `ItemType` 增加类型（如果现有类型不能复用），在 `ObjectPoolSO` 的 `itemPrefabDic` 绑定 prefab。
5. 在 `SkillPack` 的 `skillVFXType`/`bulletVFXType` 或 `SkillEffect` 中引用；不要在运行时临时 `Resources.Load` 绕过对象池。

特别注意：

- 现有 `BuffType.AutoHeal` 在 `BuffManager.ProcessBuffs` 中固定恢复 15% 最大生命，不是 35%。方尖碑的 35% 光环不能直接把 35 写进 `stacks`；需要新增百分比配置或专用效果。
- 现有 `BuffType.SlowingField` 是单体、带 `barrierHealth` 的阻速场，破盾当次仍全额吸收且无空间范围；它不能直接满足“范围内群体护盾”，B38 需要单独设计。
- `skillidle`/`skillover` 若用于护盾引导循环/收尾，先解决 `PieceDisplay` 没有对应字段的问题，再谈绑定。

### 4.6 UI、碰撞与导航

- `EnemyCanvas` 是 `Assets/Prefab/UI/EnemyCanvas.prefab` 的嵌套实例，包含血条、受击信息、Buff 根节点。复制敌人预制体后检查：
  - `EnemyController.enemyCanvas` 指向副本内的实例。
  - 血条/受击信息/Buff 的世界偏移与缩放适合新体型。
  - 头顶状态、伤害预览、Buff 图标在 1280×720 和 1920×1080 下不重叠、不遮挡。
- `BoxCollider` 只覆盖棋子本体，不要包住特效；`NavMeshAgent` 与场景 NavMesh 的半径/高度一致。
- 根节点保持 `Piece` 标签和 Layer 11；`isPlayerPiece = 0`；`deadNotDelete` 按设计决定尸体是否保留。

### 4.7 场景与 AI 登记

2. 直接放置或预放置的敌人要加入场景 `AIController.pieces`；否则不会在 `PlayerController.Init` 中初始化，也不会进入行动调度。
3. 波次：`WaveController.waveDict` 按回合登记 `EnemyController`；到回合只负责 `SetActive(true)` 与 `isActived = true`。
4. 迷雾：`FogController.enemyPiecesDict` 按迷雾区域登记；扫描后激活并开始攻击。
5. 检查 `BattleScene.prefab`/场景中的 `BattleManager.pieceDataListSO`、部署区、NavMesh 和遮挡；不要在未确认的场景里保存覆盖。

## 5. 常见陷阱

1. **只改预制体，没改 SO**：运行时 `pieceID` 查到旧数据，生命/护甲/技能全是旧的。
2. **只改 SO，没改 `pieceID`**：仍然加载旧条目，或 `GetPieceData` 找不到时报错。
3. **重复 `pieceID`**：`GetPieceData` 使用 `Find`，只会取第一个，后加的条目静默失效。
4. **手改 SO YAML**：Odin 数据在 `serializationData`，文本里的 `pieceDataList` 可能不是实际生效副本；用 Inspector。
5. **自动加载找不到序列帧**：`INST1idle0000.png` 这类补零命名不匹配 `<pieceName>idle1.png` 规则；手工绑定或统一改名。
6. **`skillidle`/`skillover` 没有入口**：`PieceDisplay` 没有这两个字段；不要假设绑定后会自动播放。
7. **护甲键写错**：热能=`Ranged(2)`、动能=`Melee(1)`、火种=`Electric(3)`；写反会导致伤害类型不匹配。
8. **`ATK`/`CON`/嘲讽以为在 SO**：它们不在 `SetData` 覆盖范围内，必须在预制体 `UnitAttrCenter` 配置或通过 `attrDic` 修改。
9. **`skillLibrary` 设置了但 ID 为空**：攻击解析不会回退旧字段，直接变空；要么完整迁移，要么先用旧字段。
10. **复制后保留旧 `UnityEvent`**：源敌人的 `SelfHeal.FullHp`、自爆、召唤会跟着复制，导致新敌人行为异常。
11. **`turnSpeedOverride` 非 0**：会覆盖 SO 的 `speed`，看起来像“SO 速度不生效”。
12. **`EnemyCanvas` 偏移没调**：血条/受击信息埋进模型或飘太高；不同体型必须重新调。
13. **Layer/Tag/`isPlayerPiece` 错**：点选、阵营、伤害和 AI 目标关系都会异常。
14. **VFX 只建了 prefab，没进 `ObjectPoolSO`**：`GenerateObject` 返回 null 并报错。
15. **把 35% 写进 `AutoHeal.stacks`**：现有 AutoHeal 固定 15%，层数不改变百分比；需要新效果或扩展。
16. **把单体 `SlowingField` 当群体护盾**：它没有空间边界，破盾当次仍全额吸收；群体护盾要单独实现。
17. **忘记 `AIController.pieces`**：场景里看得见，但不会初始化/行动；波次和迷雾只负责激活。
18. **`BattleManager.pieceDataListSO` 为空**：运行时 `GetPieceData` 直接空引用；确认 `BattleScene.prefab` 的引用。

## 6. 方尖碑示例（B36–B38）

### 6.1 已知需求

- 黑衣人的特殊无人机；在自身属性基础上，对一定范围内的黑衣人施加持续自动治疗，使黑衣人每回合恢复自身最大生命 35% 的生命。
- 【屠龙术】词条对方尖碑生效时，即可将其秒杀，并导致范围内所有黑衣人被该词条影响。
- 方尖碑免疫【逆转敌我】词条。
- 1 级生命值 = 60，防御力：热能 10、动能 5、火种 0。
- 有群体防御技能：展开范围护盾，从护盾外打里面，不论攻击单位还是护盾本身都会被拦下，除非伤害超过护盾本身的生命值。

### 6.2 制作建议

1. **复制源**：优先 `Enemy05`（黑衣人，同阵营单位）或 `Enemy00`（带 `SelfHeal` 的现有实例）；复制后清空源预制体的 `OnTurnEnd`/`OnDead` 等旧事件，移除 `SelfHeal`、自爆、召唤等不需要的组件。`Enemy00` 的 `pieceID` 1000 在 SO 中没有条目，复制后必须改为新 ID 并新增 SO 数据；若复制 `Enemy11`，必须先拆掉自爆/死亡逻辑。
2. **显示**：按 4.2 绑定 `INST1` 序列；`skillidle`/`skillover` 暂时没有字段，B36 先不做，B37/B38 需要引导动画时再扩展或合并。
3. **预制体数值引用**：`pieceID` 指向新 SO 条目；`UnitAttrCenter` 的 `_maxHealth`/护甲/`ATK`/`CON`/嘲讽按确认值同步；`turnSpeedOverride=0`；体型/碰撞/导航/`EnemyCanvas` 按方尖碑素材调整。
4. **SO**：名称“方尖碑”；`maxHealth=60`；`_armorDic` 热能=10、动能=5、火种=0；`memeBodyType` 机械；`memeTargetTags` 加“黑衣人”（屠龙术门槛）；其余数值待确认；默认等级成长是否采用也待确认，未确认不填。
5. **技能/特效**：治疗光环与护盾技能（主动施放或常驻待确认）、动画索引、音效、`FIRESEEDbarrier` VFX 按 4.5 接入；35% 治疗和群体护盾规则见 B37/B38，不要在本步自行补数值。
6. **词条联动**：逆转敌我免疫需要新的永久免疫配置或专用判定；屠龙术秒杀 + 范围传播需要方尖碑专用处理器。两者都依赖 [B37](战斗系统开发计划与验收.md#第七批新敌人与制作流程2026-11-01) 与 D13。
7. **场景**：按目标关卡加入 `AIController.pieces`，需要时登记 `WaveController`/`FogController`；确认 `BattleManager.pieceDataListSO` 引用。

### 6.3 明确不在 B36 内解决

- 35% 治疗光环的结算规则与实现（B37）。
- 屠龙术秒杀/传播、逆转敌我永久免疫（B37）。
- 群体护盾的拦截、耐久、破盾与溢出规则（B38，待 D12）。
- 任何未给出的数值（行动力、移动范围、速度、攻击、技能消耗、光环/护盾半径与耐久等）。
