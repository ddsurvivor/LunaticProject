# 代码注释规范

适用于项目新增或修改的代码。注释使用中文，保留 API、类型和字段的原名。只在以下三类位置添加注释，其余代码不注释。

## 重要外部接口：summary

跨模块调用、业务规则入口、UI/序列化事件入口和编辑器批处理入口使用 XML `summary`，说明用途及调用者必须知道的约束或副作用。对外暴露关键业务状态的属性也适用。`public` 不代表必须注释，普通数据访问器和内部装配辅助方法不必逐一补齐。

```csharp
/// <summary>按人数一次性扣除聚能费用；冷却中或余额不足时返回 false，不扣费。</summary>
public bool Spend(int actors)
```

不填写空的 `param`、`returns`，不复述方法名。只有参数单位、取值约定或返回值含义无法从签名及 summary 理解时，才补充对应 XML 标签。

## 重要实现步骤：单行注释

在关键步骤前用 `//` 说明业务原因、执行顺序约束或需要维持的不变量。例如等待动作完成后接管输入、提交费用前重新校验角色、退出时恢复普通回合状态。

```csharp
// 等待在途攻击结算，避免切换控制权时丢失伤害回调。
while (HasCombatPresentation) yield return null;
```

只标记关键步骤，不为普通赋值、循环、空值检查或每个分支写注释。不使用逐行翻译或“第一步、第二步”式流水账。

## 重要变量：行尾简单注释

在影响业务规则的状态、阈值、单位、快照和资源所有权变量声明行尾写短注释。临时 UI 引用、循环索引和含义明确的普通局部变量不加注释。

```csharp
public const float ActorCost = 50f; // 每名角色消耗的基础能量，不随容量升级变化。
int savedAP = actor.unitAttrCenter.CurMovePoint; // 退出额外行动后恢复的普通 AP。
```

多个状态含义不同，需要分别说明时拆分声明；不为了对齐注释改动整段格式。

## 维护与检查

- 注释必须与当前行为一致，明确区分已实现规则和待办，不把设计愿望写成现有行为。
- 修改逻辑时同步更新相邻注释；删除空注释、失效注释和重复说明。
- 不为补注释修改业务逻辑、接口签名或序列化字段名，也不批量重写历史文件。
- 纯注释修改检查差异、注释语法和非注释代码是否一致；不新增复述实现的测试。
