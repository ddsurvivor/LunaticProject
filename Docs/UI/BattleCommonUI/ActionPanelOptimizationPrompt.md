## 1. 面板打开：等间隔依次缓动出现

- 一级菜单打开、二级菜单新展开/切换分类时，按最终可见顺序逐个出现。禁用但可见的行参与计时；隐藏行不占位置或时间。
- 同一次展开的相邻行使用固定间隔，间隔随可见按钮数量变化；不能所有数量都固定 0.2 秒，也不能越往后越快。
- 本轮采用以下明确算法，时间均为秒：

```text
n = 最终可见行数
d = 0.20                         // 每行完整缓动时长
T = 0.80                         // 整批从开始到最后一行完成的上限
interval = n <= 1 ? 0 : min(0.20, (T - d) / (n - 1))
startTime(i) = i * interval       // i 从 0 开始
finishTime = n == 0 ? 0 : (n - 1) * interval + d
```

| 可见行数 | 开始间隔 | 最后一行完成时间 |
|---|---|---|
| 0 | 无动画 | 0 |
| 1 | 首行立即开始 | 0.20 |
| 2 | 0.20 | 0.40 |
| 4 | 0.20 | 0.80 |
| 10 | 约 0.0667 | 0.80 |

- 动画默认淡入配小幅位移，使用柔和 EaseOut；参数集中配置。布局占位与动画视觉分开，避免布局组和 Tween 同时修改同一个 RectTransform，造成跳动或按钮重叠。
- 未出现的行不得响应点击；出现后的行依据业务可用性响应。按面板刷新率或 Time.timeScale 改变不应破坏菜单动画，可使用 unscaled time。
- 关闭、重开、切换角色、切换分类时取消旧序列并还原位置、透明度、射线与交互状态；旧完成回调不能重新显示已关闭的菜单。

## 2. 消耗列与分类箭头互斥

- 明确区分“执行动作按钮”和“展开分类按钮”。执行动作显示真实 AP 消耗；技能、攻击及其他实际拥有二级菜单的分类按钮在同一列显示三角形箭头，隐藏 AP 文本。
- 使用独立三角 Sprite/Image，不再用 `›` 字符代替三角形。折叠态保留统一初始朝向；展开时相对初始朝向顺时针旋转 90°，收起/切换时回到初始角度，禁止累积旋转。
- 分类展开本身不扣 AP、MP 或弹药，也不触发任何消耗预览。只有二级菜单中的具体技能、近战/远程攻击、道具、警戒指令等按实际规则显示费用。
- 待机显示当前全部剩余 AP；真正零消耗的执行动作可以显示 0 AP，分类不能显示 0 AP 冒充动作。

## 3. 二级菜单相对触发按钮垂直居中

- 正常情况下，二级菜单可见面板的垂直中心与触发它的一级按钮的垂直中心对齐，而不是对齐一级菜单顶部或触发行上边缘。
- 在同一 Canvas 坐标空间内，以触发按钮实际 Rect 中心定位，纳入 CanvasScaler、父级变换、相机和滚动偏移。
- 水平方向位于父按钮侧边并保留统一间距；右侧空间不足时向左展开。
- 超出视口时，优先将整组菜单平移以保持中心关系；仍放不下时限制二级可视高度并滚动。边界钳制优先于绝对居中，禁止为居中把菜单移出安全区。
- 使用二级菜单的可见 viewport 高度计算中心，不使用所有条目累加后的完整 content 高度。相机移动/缩放、一级列表滚动与分辨率改变后持续保持正确关系。

## 4. 展开后的父按钮保持选中并锁定重复点击

- 同时只展开一个二级菜单。父按钮展开后保持点击后的选中视觉，箭头保持旋转态，离开鼠标也不恢复普通态。
- 已展开的父按钮不再响应重复点击，不重复创建列表、重播展开动画或累积监听器；本次定义为“重复点击不收起”。
- 点击另一个分类时，旧分类恢复正常、箭头归位，旧内容/预览清理，再展开新分类。关闭整个面板或切换角色时解除所有分类锁定。
- “展开锁定”与“资源不足禁用”必须是不同状态。锁定的父按钮保持选中样式，不能因为拒绝再次点击就变成灰色禁用态。

## 5. 按钮状态统一且可读

| 状态 | 外观与输入 |
|---|---|
| Normal | 正常文字、底板与描边，可点击 |
| Hover | 可用按钮高亮并从左侧中心缓动放大；可执行动作触发资源预览 |
| Pressed | 按下瞬间的视觉反馈，与悬停可区分 |
| ExpandedLocked | 分类持续选中、箭头转 90°，不接受重复点击，不因移出而取消选中 |
| Disabled | 直观弱化，AP 文字变灰；不点击、不高亮、不缩放、不启动资源呼吸；技能/道具仍可悬停显示详情 |

- 状态由统一脚本集中管理，不能让 Button ColorBlock、ActionBtn、HoverScale 和多个 Tween 各自覆盖颜色/缩放。
- 一级/二级菜单不绘制整块底板，保留各按钮自身底色与边框；菜单空隙可保留透明命中区域防止误点棋盘。
- 可用按钮悬停默认放大至 1.06 倍，以视觉子节点的左侧中心为锚点，0.12 秒缓动；相邻行距至少 6px，并根据放大倍率预留纵向间距和横向/顶部/底部裁剪余量。布局根不参与缩放。
- 将详情悬停与可操作反馈分开：技能/道具不可用时仍显示完整详情，但不高亮、不缩放、不启动费用呼吸。移出按钮立即清理费用预览，详情保留默认1.25秒的可配置转移宽限；鼠标进入详情区后可持续阅读和滚动，离开后超时关闭。切换条目/分类、关闭菜单或进入动作流程时立即清理旧详情。其他不可用原因如已有数据可常态显示。
- 技能等分类按钮在角色仍可操作、面板允许交互时通常一直可展开；即使其所有子项都因 AP/MP/弹药等不足而禁用，分类本身仍可点击查看。
- 子动作仍按真实业务可用性禁用；不能用“菜单需要可点击”绕过角色控制权、死亡/眩晕、行动中或转场限制。
- 当资源或角色状态变化时同步更新可用性，点击提交前仍走原业务校验，避免悬停后状态变化导致错误扣费。

## 6. 统一 ActionButton 预制体和脚本

- 建立可复用的 `ActionButton.prefab`（放在现有战斗 UI 资源目录），一级动作、一级分类和二级条目均使用它及同一按钮脚本；差异由绑定数据决定。
- 预制体包含清晰的名称、消耗列、三角箭头、背景、描边、动画视觉容器和必要交互组件。正式流程不再依赖运行时临时 AddComponent/克隆 Text 来拼齐缺失结构。
- 名称/消耗/箭头使用稳定列；长中文和英文名称均不挤占消耗列。所有装饰 Graphic 关闭 Raycast Target，交互区域保持连续。
- 按钮脚本负责显示、状态、动画和事件转发；面板负责列表、分类和定位；资源预览由一个明确的协调入口控制；实际扣费与攻击/技能逻辑继续属于原战斗业务。保持类和接口简洁，不为本次重构引入庞大通用框架。
- 可以复用按钮池；复用前清理事件、选中状态、费用、箭头、Tween、提示和旧角色引用。切换与反复打开不重复绑定。
- 不再用 `Enum.GetValues` 的顺序对应一个 Button 数组。使用显式动作/分类绑定与明确展示顺序，以免枚举改名或增项导致按钮串位。
- 将共用 BattleScene prefab 和实际场景切换到新入口，检查 overrides，清除旧菜单表现逻辑的重复执行；保持业务引用完整。

## 7. 悬停预览真实 AP、MP 和弹药消耗

### 7.1 费用来源

- 以当前行动者和具体动作数据生成只读费用预览；显示、可用性判断和预览采用与实际执行一致的费用来源。
- AP 从 GameConstSO/现有最终费用规则读取，待机取当前剩余 AP；MP 使用 `UnitAttrCenter.GetSkillManaCost(skill)` 等最终消耗入口，考虑装备等修正；弹药从真实攻击/动作规则获取。
- MP 在本文指能量 Mana，不是代码历史命名中的 MovePoint。不要把技能消耗道具、弹药和能量混为一类；也不要给本来没有弹药费用的技能凭空显示弹药消耗。
- 若缺少统一只读查询，可小范围提取并复用既有费用计算。禁止在悬停时调用 CostMP/CostMana/CostAmmo 或模拟执行来取得费用。

### 7.2 预览表现

- AP：在当前选中棋子身上的实际 AP 图标中，从右向左选择即将消耗的可用点进行平滑呼吸。2 AP 动作闪烁最右侧两个可用图标；已消耗的空心点不闪烁。
- 示例：6 点容量、当前剩 4 点，消耗 2 AP 时只闪烁第 3、4 个实心点，不是容量末尾的第 5、6 个空心点。0 消耗不闪烁，待机闪烁全部剩余实心点。
- 必须核实并接入“棋子身上”的实际显示组件；不能只修改左下信息面板就宣称完成。左下对应资源显示若同步预览，与角色身上共享同一费用和清理时机。
- MP：参考损血预览叠加一段呼吸高亮，范围为 `[max(0, current-cost)/maxValue, current/maxValue]`。闪烁的是即将消耗的区间，而不是整条能量条或真实填充值。
- 弹药：若是图标，闪烁最右侧即将消耗的可用弹药点；若是条形显示，用相同消耗区间叠层表达；保留真实数值。不得将预览误显示成已经扣除。
- 呼吸采用平滑周期而非突兀开关，可调周期/最低透明度；移出恢复原阵营/资源颜色和 alpha，不一律恢复成白色。最大值为零时不得除零。

### 7.3 生命周期

- 仅可执行且可用的具体动作触发费用预览；分类按钮、禁用按钮不触发。
- 从 A 移入 B 时先清 A 再展示 B；同一行动者同一时刻只有一份悬停费用预览。
- 单纯移出按钮、分类切换或关闭菜单时清理悬停预览；确认具体动作进入范围选择时，由独立于菜单显隐的行动展示逻辑接管相同费用，持续呼吸直到实际确认执行或取消。选择中资源变化仍重算费用。
- 正式扣费时停止待消耗预览；取消、角色切换、目标离场、对象禁用/销毁时清理接管状态，不能残留旧角色的效果。
- 持续悬停时资源变化，要重算或结束预览；不要污染当前数值刷新、HP 损伤动画或下一名角色的 UI。

### 7.4 AP 消耗动画与行动后返回

- 实际 AP 减少后，消耗掉的实心点以独立视觉图层使用 DOTween 同时放大到2倍、淡出到0，持续1秒；原点立即显示真实剩余状态。初始化、恢复 AP、切换角色和容量调整不触发消耗动画；禁用或换源清理未完成效果。
- 等真实移动、检定、弹道、攻击及反应表现全部结束后，镜头重新跟随当前行动棋子；仍有控制权和剩余 AP 时重新构建并展开行动面板。取消范围选择也恢复可操作目录。已交棒、角色失效或外部控制接管时，不得拉回旧角色或重开旧菜单。

## 8. 近战和远程归入新的“攻击”分类

- 一级菜单将“近战攻击”“远程攻击”合并为一个“攻击”展开入口；二级中分别显示角色拥有的这两种攻击及各自真实费用/可用状态。
- 一级“攻击”只负责展开，使用三角箭头、不扣费、不启动攻击、不启动消耗预览。即使子项当前都不可用，只要角色拥有攻击能力且菜单允许操作，仍可展开查看。
- 只有一种攻击能力的角色，二级只显示该种；两种都没有时不增加攻击能力，不强行显示虚构动作。其他分类遵循相同的“拥有能力/目录”与“当前付得起费用”区分，空列表给出明确空状态。
- “攻击”是 UI 分类，不必新增可执行 ActionType。保留近战/远程原有业务入口、目标规则和费用，不把二者合并成一种战斗规则。

## 9. ActionType 英文标识、中文标签与运行时双语

## 10. 实施顺序与验收

按“现状与费用/序列化核查 → 统一按钮预制体及绑定 → 分类与状态 → 动画和定位 → 资源预览 → 双语与兼容迁移 → 真实场景回归”分批实施。动画算法、状态表、预览归属必须先明确再接入。

至少覆盖：

1. 原“只显示移动”的回归：所有应有动作均正确出现，costText/arrow 等无空引用，反复打开无重复监听。
2. 0/1/2/4/10 行出现时序，实际记录首行开始、相邻间隔与末行完成；动画过程中关闭、重开、切分类无残留回调。
