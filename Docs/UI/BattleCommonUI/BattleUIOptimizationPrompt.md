## 1. 当前成果与必须保持的设计

用户已认可左下信息面板的风格，以当前项目中的实际预制体为准：

- `Assets/Prefab/Battle/BattleScene.prefab` 的 `PieceInfo`，PR2BATTLE 等战斗场景通过预制体继承。
- 深蓝黑底、细铜金边、45° 切角、米白文字、青色行动点。不要重新设计一套风格。
- 头像采用已有 PC 系列立绘；当前预览为 `Assets/Resources/CG/PC01C1.png`。RectMask2D 裁成半身，头肩露出装饰框，名字位于头像下方。运行时跟随选中角色，不固定 PC01。
- 右侧只显示行动力、生命、能量、弹药。不要重新加攻击、防御、速度。
- 行动力采用多个菱形：实心青色代表可用，空心铜金代表已消耗，每个点代表 1 AP。容量来自真实角色数据，不固定成参考图的 3 点或预览的 6 点。
- 血条 Rect 高 12px，能量/弹药条高 8px；标签左对齐、当前数值右对齐、最大值独立对齐。
- 新增 `SceneBackdrop` 位于整个面板最底层：520×336，局部位置 (-10,-10)，颜色 #0B1015，alpha=0.68，Image.Sliced，Raycast Target=false。覆盖头像背后与信息区，衬托复杂场景。它是当前设计基线；如真实场景发现过暗或覆盖过大，可以小幅调整并给出对比证据。

资料与资源：

- `Docs/UI/BattleCommonUI/README.md`：配色来源、素材切分、布局说明。
- `Assets/A美术/BattleCommonUI/`：39 张白色透明 PNG；用组件颜色染色，按 manifest 设置 Sliced/Filled/Simple。
- `Assets/Scripts/Battle/Tool/GameConst.cs` 的 `UIColors`：已采样的 AVG 色板和战斗扩展色，优先复用。
- `Assets/Scripts/Battle/UI/ActionPointPipsUI.cs`：现有行动力点阵组件，复用或小幅扩展，避免重复实现。
- `Tools/Art/generate_battle_ui.py`：设计示意图生成器，修改设计时同步；生成图不等于真实战斗运行截图。
- GitHub skill：`https://github.com/Unity-Technologies/skills/blob/main/skills/ui-ugui/SKILL.md`。环境已有同款 Unity uGUI skill；按层级、锚点、布局、可读性规范执行，不必重复安装。现有运行时是 uGUI，保持原绑定；不要为换字体系统而无差别重建全部 Text。

## 3. 优化清单：按优先级分批实施

### P0 — 棋子旁的一级行动列表

入口：`Assets/Scripts/Battle/UI/PieceActionListPanel.cs`、`ActionBtn.cs`、`UIManager.cs`、`ClickManager.cs`，以及 BattleScene prefab 中对应对象。

调整：
- 采用 MenuRowFill/MenuRowOutline，紧凑纵向列表；文字、消耗、二级箭头各占稳定列。复用左下信息面板配色、边距和切角。
- 菜单整体加半透明深色背板，便于在亮地面、草地和角色立绘上阅读。装饰层不拦截射线，按钮保持可点击。
- 跟随棋子世界位置转 Canvas 坐标。去除硬编码屏幕宽度判定；使用当前 Canvas、相机、缩放和安全边界。靠右向左展开，靠底向上移动，包含二级菜单的总尺寸不能出屏。
- 只显示现有可用动作：移动、近战/远程攻击、技能、道具、警戒指令、待机，以及条件装填/交互。不要凭示意图增删战斗能力。
- 区分正常、悬停、选中、禁用。待机消耗当前全部 AP，不能显示 0 AP。其他消耗取当前配置。

验收：选中棋子后列表确实出现在其身边；镜头移动/缩放后仍正确跟随；屏幕四角、不同可用动作数量、AP 不足均不出屏、不重叠、不误触底下棋盘。点击动作走原业务流程，重复展开不累积监听器。

### P0 — 技能、道具、警戒二级菜单

入口：PieceActionListPanel 的技能/道具/指令打开逻辑及当前技能数据接口（先读最新代码）。

调整：
- 二级菜单在一级列表旁展开，与触发行建立明确视觉关系，空间不足时整体翻转；保留一级当前项高亮。
- 行内容对齐：名称、真实消耗、可用性/冷却等已有状态。长名称换行或截断并可看完整说明。
- 条目超过可视高度时滚动；不要把列表拉出屏幕。若使用 ScrollRect，阅读 uGUI skill 的 scrollview 说明。
- 从一级切换技能/道具/指令时清除旧内容；关闭面板时同时清除悬停提示。

验收：空列表、1 条、很多条、长中文名称、不可用项、反复切换分类、关闭后重开、角色切换；按钮不串数据，隐藏条目不留占位，不重复扣费。不要人为改动角色技能配置来制造结果。

### P0 — 左上角技能/道具详情

入口：`Assets/Scripts/Battle/UI/SkillTooltipUI.cs`，以及二级菜单 HoverScale 的进入/离开事件。

调整：
- 固定左上角，避开顶部速度条和安全边界；不是跟随鼠标的悬浮窗，也不是右下详情卡。
- 使用深色半透明底、细边、标题/消耗/描述分层。只展示实际已有的数据与单位；没有可靠预测接口时不要伪造命中率/预计伤害。
- 内容区域随描述长度合理伸展，最大高度受视口限制；超长内容可滚动。
- 保持现有生命周期：悬停显示，移出隐藏；点击技能后关闭菜单及提示，进入选择目标。

验收：技能/道具连续悬停、长描述、空字段、切换角色、取消或提交目标后没有残留提示；1920×1080 和 1280×720 下文字完整且不遮住速度条。

### P0 — 敌我共用头顶状态

入口：`PieceHeadUI.cs`、`PlayerHealthBarUI.cs`、`EnemyCanvas.cs`、`BuffCell.cs` 及其实际 prefab/数值驱动代码，先核实职责。

调整：

## 4. 实施与验收方法

- 按 P0 → P1 → P2 小批落地；每批先列修改对象和状态，再修改并运行验证。只动相关 UI 和绑定，不改战斗数值或技能规则。
- 对原场景和共用 prefab 的差异做检查，避免预制体 overrides 掩盖改动。接入真实场景，不能只交付独立 prefab 或 PNG 示意图。
- 最少覆盖 1920×1080、1280×720、一个非 16:9 比例（如 1920×1200）；从当前安全区和 CanvasScaler 推导布局，不凭固定屏幕坐标推算。
- 在明亮地面、暗背景、复杂纹理、角色重叠处检查文字/轮廓和底板透明度；底板只覆盖必要区域。
- 进入 Play 后确认帧数在递增、角色状态确实更新，再截图；截图不是运行证据的唯一来源。
- 原场景验收至少完整走一次：选棋子 → 一级菜单 → 技能二级菜单 → 悬停左上详情 → 点击进入瞄准 → 取消 → 重开 → 合法施放 → AP/血量/头顶状态刷新 → 行动者切换。
- 使用游戏已有接口/输入完成验证。临时驱动如确有必要，源码、结果、截图全部放项目根 `tmp/`，不入 Git；必要临时 Unity 入口执行后清理。不要留下正式代码对测试类型的依赖。
- 保留变更前后截图，并记录场景、分辨率、角色、动作、真实数值和验证结论。失败/未覆盖项明确标记；独立预览只能作为布局补充证据。
- 检查编译、Console 新增错误、空引用、缺失 sprite、重复监听、遮挡/射线；运行与改动相称的检查，不无理由扩展全项目测试。
- 若编辑器连接仍受阻，完成可执行的安全修改和独立验证，写明具体阻塞及原场景未验收项；不要宣称整项通过。
