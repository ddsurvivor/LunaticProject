# 聚能系统：速度条适配与新思路核对

更新日期：2026-10-16。设计参考：`D:/Downloads/聚能系统新思路.docx`（包括动力脊升级示意图）。原始 Word 文档未修改；本文记录实现状态和后续待办。

## 本次可使用的流程

1. 普通战斗中，我方命中敌人或实际损失生命值会充能。初始容量 100，达到 50 且不在冷却时即可发动。
2. 我方或敌方棋子行动时均可点击聚能。正在飞行的弹道、移动和一次性动作先完成，然后暂停普通行动调度，进入选人。
3. 点击我方存活、可控制且未眩晕的棋子进行选择，再点一次取消该角色。可以多选，每人需要 50 能量；再次点击聚能按钮确认，右键取消选择。
4. 按选择顺序控制这些角色，每人获得一份完整的额外 AP。AP 用完或待机后自动交给下一名；也可以点击“结束聚能”提前结束。提前结束不退还已经确认支付的费用。
5. 全部角色完成后自动退出。保留未花掉的能量，开始 3 个普通棋子回合的冷却；冷却期间仍能充能。
6. 若打断敌人，结束该敌人剩余 AP，交回速度队列；若在我方普通回合发动，则恢复原角色发动前剩余 AP，继续原回合。

聚能不会重置或推进普通行动条。额外 AP 使用完后恢复该角色原有普通 AP；不会重复调用普通 TurnStart/TurnEnd，也不会额外结算 Buff 回合持续时间。普通棋子的 Buff 仍按自身普通回合结算，按行动触发的技能/状态仍沿用原逻辑。

## 数值与配置位置

`Assets/Scripts/Battle/Controllers/BurstGauge.cs` 定义基础容量、每人费用、容量倍率、充能倍率和冷却。

| 动力脊等级 | 最大容量 | 充能倍率 | 满槽最多人数 |
| --- | ---: | ---: | ---: |
| 未升级 / 序章 | 100 | 1.00 | 2 |
| 1 | 130 | 1.00 | 2 |
| 2 | 160 | 1.10 | 3 |
| 3 | 200 | 1.21 | 4 |

等级 3 的获得率按设计图“在二级基础上 ×1.1”解释为 1.1 × 1.1。每人费用固定 50，不随最大容量上升。人数也受场上可选角色数限制。

在 `PlayerController` Inspector 中设置 `powerSpineLevel`（0–3）。`forceDefaultBurstCapacity` 用于明确强制教学/序章基础容量。`chapterNumber == 0` 是当前临时章节判断；章节信息缺失也可能保持为 0，正式接入关卡数据前需留意。

单次命中/受伤基础充能继续使用 `GameConst.attackBurstCharge` 和 `GameConst.hurtBurstCharge`。聚能调度在 `BattleManager.BurstTurns.cs`，与普通速度回合的衔接在 `BattleManager.SpeedTurns.cs`。

## 尚未实现的内容与建议顺序

1. **精确的范围伤害/爆炸免疫**：为伤害结算传递来源、范围类型和聚能归属。不能在 TakeDamage 中简单屏蔽所有伤害，否则会误吞持续伤害、自损或普通单体攻击。验收应覆盖敌方 AoE、友方爆炸连锁、非聚能队友和退出后的伤害。
2. **受击首帧冻结与统一释放表现**：为角色受击、场景破坏、爆炸物建立延期表现队列，区分数值结算与视觉播放。需要协调死亡隐藏/销毁、对象池、击退移动、连锁爆炸和战斗胜负判定；不能仅停止动画。退出、取消、胜负和场景卸载都需要清理。当前保留即时结算。
3. **设施与存档接入**：读取夜巡号动力脊实际等级，升级界面写入存档，战斗初始化读取；目前只有 Inspector 配置入口，不会自动读取设施进度。
4. **教学/序章关卡绑定**：用明确的关卡元数据替换章节编号 0 的临时判断，并确保所有教学入口强制基础容量。
5. **完整灰度覆盖与视觉验收**：检查场景装饰、特殊材质、粒子是否都需要褪色；验证多人选中提示、按钮文字、闪屏和速度条在真实战斗中的表现。当前仅沿用已有材质覆盖范围。
