# 战斗反应队列与 B09 验收

## 本次实现范围

B09 在已确认的现行规则上整理击退、夹击和警戒时序，不修改伤害公式、碰撞基数、识别门槛或模因的反应开关。核心实现位于 `BattleManager.Reactions.cs`，复用 B08 的 `BattleActionContext`。

- 命中时登记夹击检查，等待原攻击、受击、识别结算和所有在途击退结束，再按实际落点选择最近的有效队友。碰撞扣血先于夹击选择。沿用最近一名队友、`ableStrick` 和夹击期间不再派生夹击的限制。
- 同一根行动的夹击检查按攻击者/目标去重，实际夹击再按队友/目标去重；警戒按警戒者/目标去重。异步行动持有同一根的预算，出队不返还次数；记录随根上下文释放，不建立跨战斗的永久索引。
- `maxReactionDepth` 默认 8，`maxReactionEvents` 默认 64，可在 BattleManager Inspector 调整，最小为 1。后者同时约束每根累计接纳事件与全局等待队列长度。夹击资格检查也占一个事件；上限用于终止失控链，不新增伤害倍率。
- 队列逐项执行，重查存活、启用、阵营、敌人激活、指令是否仍有效、攻击配置、认知保护及必要资源。夹击检查眩晕但不新增 `OnAction` 自损触发；警戒保留原 `BuffManager.OnAction` 行为。父上下文只在同步推进结算时进入，不跨帧持有。
- 警戒在确认时快照扇形方向，检查每段实际移动的水平线段与环形扇区是否相交；保留原半径、角度和 1 米内圈。移动结束前补查最后一段，两个端点均在区外也能捕获穿越。被捕获的单体攻击不因目标随后离开而丢失；敌方范围攻击仍沿现有范围查询，不扩展命中名单。
- 玩家与敌人警戒都在成功发动攻击后消耗 `maxTriggerCount`，耗尽后解除；排队期间不重复提交，未成功出手不消耗次数。按阵营清理警戒时，不再直接丢弃另一阵营的记录。
- 击退纳入共同表现锁。同一棋子再次击退会取消旧位移，取消时不补碰撞；保留原 Agent 启用状态。胜负、退出、禁用和场景卸载清空队列、警戒跟踪及本场击退，同时取消队列当前持有的反应攻击与弹道，用版本防止旧回调补发碰撞。
- `PieceController.GetRange` 在相应普攻缺失时返回 0，避免 AI 的射程读取空引用；不替角色生成或配置技能。

## 验收环境与边界

使用 Unity 2021.3.23f1，在项目 `tmp/` 下的隔离副本运行 `Assets/Scenes/PR4-2BATTLE.unity`。独立公司/产品名使存档路径与正式项目分离；没有保存正式场景、技能库或角色资产。

隔离副本第一次读取沿用旧导入缓存，角色技能库引用为空；对两份配置强制重新导入后恢复引用。之后仍观察到部分普攻无法按 ID 解析、部分动作没有实际伤害提交。原始读数保存为 `units.json`，这一现象不归为 B09 队列通过，也不据此改写正式技能配置。

因此反应矩阵采用 PR4-2 的真实角色、动画、伤害管理器、Buff、DOTween、NavMeshAgent、生命/死亡回调和正式胜负入口，临时在内存中给受测角色配置小伤害普攻和充足生命值，并在场景远端建立可控 NavMesh/墙体。不会将此受控矩阵描述为原始关卡自然战斗通关或技能迁移验收。
