# 战斗伤害与行动上下文接入

更新：2026-10-29，B08。现行伤害、识别、掩体及计时规则沿用[B07兼容基线](战斗规则决策表.md)，本次不采用新玩法数值。

## 入口与来源

所有现有伤害仍由UnitAttrCenter提交生命变化；新增带BattleDamageSource的TakeDamage重载。旧单参数调用保持可用，来源为Unknown，不重复扣血。自定义扩展应显式提供来源。

| 当前入口 | 来源分类 | 行动与归属 |
| --- | --- | --- |
| DamageManager.ResolveSkillTarget | Skill | 攻击者、技能及显式或当前行动；多目标PieceSkill共用行动，各段保留同一根ID |
| 普通桶/电浆桶/自爆召唤物 | Skill | 沿用原PieceSkill路径，施法者为环境对象；普通桶与电浆延迟回调捕获触发时根行动。原归属和死亡施法许可不变 |
| BuffManager回合持续伤害 | Periodic | 旧BuffState没有施加者/原始行动信息，因此不猜测施加者；本次持续结算有独立ID。完整状态来源传播随B10处理 |
| 旧行动前异常伤害 | ActionEffect | 标记承受异常并发起该行动的角色，不将其当作已知的状态施加者 |
| 击退碰撞 | Collision | 安排位移时捕获施法者与根行动，回调不读取届时其他角色的行动 |
| SelfExplosionEffect | SelfDamage | 保留自损100及原类型，当前行动内带入施法者 |
| 插件蛛丝直伤 | Component | 插件原有固定伤害和被动通知顺序不变，附攻击者/技能与当前根行动 |

爆炸物Skill分类不表示其伤害是单体，也不自动授予免疫；精确范围标签和免疫规则属于B14。召唤物自主探索造成的攻击建立自己的行动，不自动把多回合后的伤害归给召唤者。

## 实际生命结果与事件

带来源的TakeDamage返回BattleDamageResult，包含Target、Source、Requested、HealthBefore、HealthAfter、HpLoss、Killed、Ignored。结果在生命回调和死亡逻辑前固定，后续被动治疗等不会改写该段快照。伤害公式输出与DamageInfo继续使用原有数值，不把展示/聚能/碰撞基数静默改为实际掉血。

每次有效提交完成后，UnitAttrCenter.DamageApplied发送一次结果；零伤害有事件且HpLoss为0，保留受击表现。死亡目标与负伤害被忽略且不发事件；致死后原段循环停止，不重复通知死亡。屏障全吸收在DamageManager内部结束，不调用TakeDamage，也不发生命提交事件。DamageManager.Settlement.DamageResults保留本次实际进入生命提交的各段结果，屏障吸收不在其中。

现有NotifyHpChanged、NotifyTakeDamage、NotifyKillEnemy和受击回调仍按原有入口执行；本次没有把DOT/碰撞等强行接到旧技能被动通知上，避免扩大现行触发范围。新规则若需要统一观察各类实际掉血，应订阅DamageApplied，而不是同时把它与旧NotifyTakeDamage当成两次伤害。观察者不应再次扣除已提交伤害，销毁或换场景时自行解除订阅。

本轮不提供未命中/屏障吸收的完整战果日志，也不改变伤害事件重入、状态解除或反应优先级；这些需后续结算/反应服务处理。

## 根行动及异步边界

BattleActionContext提供进程内单调递增ActionId、RootActionId、Actor、Skill和IsReaction；不作为持久化技能ID或存档ID，不实现撤销快照。新子行动继承当前或显式父行动的RootActionId。该ID只用于关联，不自动去重伤害，也不代替B09的反应上限和根行动去重键。

MemeActionContext继续负责原有来源合并和尝试去重，并持有Action。旧调用创建的空Action只在真实PieceSkill入口通过EnsureAction补齐一次，检定等待恢复时仍复用。模因预览显式使用isPreview，不分配行动身份。

Enter作用域只用于同步主线程结算；using退出或异常时恢复父上下文。不得跨yield或动画等待保持全局Current。弹道沿用CombatActionRoutine已有MemeActionContext，识别等待沿用已有上下文；延迟碰撞、延时技能、夹击及桶引信各自捕获并在同步回调中恢复根行动。新建异步扩展同样必须显式捕获，不能在回调触发时直接读取Current来推断原行动。

费用提交时机、延时技能触发时点、桶引信、AOE目标顺序、夹击顺序和状态持续均保持原有实现。本轮不修复或重写B09/B15/B19的生命周期问题。

## 随机源与恢复

BattleRandom统一暴露整数/浮点Range、Value及CaptureState/RestoreState。伤害暗骰、识别、模因、旧Buff概率、插件、战斗被动、敌人AI采样/选择、楼梯接近点和队伍面板随机生命值已改用该入口。暗骰仍为四次1–6采样，现有概率比较符、边界和短路条件保持原状。

后端仍是UnityEngine.Random，全局状态与自动战斗宿主现有InitState及退出恢复兼容。移除了DamageCalculator单独的System.Random，因此旧版本同种子结果不保证逐次一致；骰子分布及B07公式保持不变。表现噪声UIPanel、轮廓采样ObstructionOutline、场景转场图选择及剧情骰子仍直接使用Unity随机，它们也共享同一底层序列。

CaptureState本身不消费随机数；直接伤害预览穷举原有分支，不调用BattleRandom，不产生生命事件或行动ID。RestoreState会同时回滚共用Unity序列的表现/剧情调用，应在稳定边界使用。当前没有独立的战斗随机流、跨版本回放保证或完整场景快照；若未来要求隔离，需连同表现、剧情和自动战斗一起设计迁移。
