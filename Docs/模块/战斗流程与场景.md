# 战斗流程与场景

正式调度由 BattleManager 各 partial 文件协作完成。开战与部署看 Startup/Deployment，普通速度回合看 SpeedTurns，聚能接管看 BurstTurns，外部命令看 ExternalControl。输入和自动玩家均经正式命令校验、扣费与表现入口，不直接修改目标生命。

## 正式启动

### 正式入口

`StartScene` → 点击“新游戏” → `OPCG` → `Playing` → 自动开始 `PR0`。

- Build Settings：StartScene 第一位，OPCG、Playing 已启用；保留 AVG 原有启用状态，未启用其他战斗/调试场景。
- StartScene 实际按钮的 `onPointerUp` 绑定 `StartMenu.OnClickStart`，菜单目标为 OPCG；空配置同样回退 OPCG。
- 新游戏创建全新 PLAYERPROFILE，清空残留特殊剧情和战斗设置；转场期间重复点击不重建档案，不覆盖原有磁盘存档。
- OPCG 保留同一 GM 与档案，正常播放结束后展示 LOGO/文本并进入 Playing；Esc 或 `Openning.Skip` 可跳过。视频缺失、错误、准备/播放超时均继续后续流程；离场清理本片头动画和视频回调。
- Playing 关闭 `isDebugMode`，由 GM 转场完成后调用地图剧情入口，自动开始 PR0 并消耗新游戏标记。
- 编辑器/Development 审核辅助仅在进入 AVG 后安装审核档，不在正式启动时注入。安装新审核档后刷新 DataManager，保留原有审核功能。

## 关卡搭建

预制体目录：`Assets/Prefab/Battle/Authoring`。

把预制体拖进战斗场景，在对应脚本里修改尺寸。根节点的 Transform 只用于移动和绕 Y 轴旋转，缩放会被组件自动纠正。建议父节点保持单位缩放。参数在编辑器中修改后自动刷新，也可以点击 Odin 的「检查并刷新」按钮。

### 障碍物掩体

使用 `障碍物掩体.prefab`，在 `BattleObstacle` 中设置宽、高、深和图片。BoxCollider 与 NavMeshObstacle 自动同步，导航障碍开启 Carving；地面本身需要已有可行走 NavMesh。

「提供掩体」开启时接入现有 CaverSlot 掩体判定，可设置闪避与减伤数值；关闭后作为普通障碍物。点击「归位到 Y = 0 并刷新」会把根节点移回地面，并同步图片和碰撞体。

### 高层平台

使用 `高层平台.prefab`，在 `BattlePlatform` 中修改宽、深、平台高度、顶面图片和侧面图片。高度相对于根节点 Y；例如根节点 Y 为 0、高度为 3，平台顶面就在 Y = 3。

平台自动生成顶面的可行走 NavMesh，修改尺寸、高度或位置时替换旧导航，并同步实体碰撞和顶面、侧面图片。运行时启用组件也会生成导航，无需保存额外的导航资产。「导航已生成」可检查生成状态，默认 Agent Type ID 为 0，与现有棋子一致。

高低层之间的通行仍需按关卡设计放置现有 LadderArea 等连接设施。平台不会自动生成楼梯或跨层传送点。

### 角色出生区域与整备部署

使用 `角色出生区域.prefab`，在 `BattleDeploymentArea` 中设置矩形宽、深。支持绕 Y 轴旋转，同一战斗场景可以放置多片区域。绿色范围只作显示，不阻挡物理碰撞和导航。区域需要覆盖已有的可行走 NavMesh；放在高台上时，将根节点 Y 设置为平台顶面高度。

场景存在启用的出生区域时，BattleManager 在原有开战流程前进入部署阶段：

1. 保留己方可控制棋子的合法站位；其他棋子尝试在各区域内寻找空位。
2. 左键选择己方棋子，再点击任意绿色区域调整位置；右键或 Esc 取消选择。
3. 棋子整个占地必须在同一片区域内，不能与其他棋子或实体障碍重叠，不能跳到其他楼层。部署不消耗行动力。
4. 点击「开始战斗」后检查所有可控制棋子的站位。检查通过后隐藏区域，继续原有开场与回合流程；空间不足时会提示调整，不能直接开战。

这里调整的是现有队伍棋子的站位，不负责创建队伍成员。没有出生区域的旧场景沿用原有开战流程。

## 重开与战前快照

### 实现范围

- 战斗初始化前保存完整战前档案，普通战斗使用独立工作档案。胜利、失败和暂停窗口均可重开，恢复战前状态，重新载入场景并进入部署。聚能、模因状态、速度队列及战斗日志随场景重建。旧场景先停用，再恢复档案，避免残留行动污染新一轮。
- 没有配置部署区的旧场景在我方出生点附近生成回退部署区；放置仍须通过导航、地面高度和占用检查。部署提示位于画面顶部。
- 整个战斗会话及重载期间禁止档案保存；胜利离场提交奖励，暂存的成就及通关标记在离场提交。重开、放弃或部署退出不提交本轮结果。
- 默认恢复同一初始种子和随机状态；GameConstSO 的重开重掷选项可生成新种子。临时自动战斗宿主保持其原有档案和随机状态管理。

### 验收边界

Steam 平台实际成就提交及非临时档案的通关文件写入未连接真实外部服务或落盘验证；已验证其暂存、重开清理及离场路径。Unity 全局随机流仍可能被表现或其他调用消耗，因此同种子不保证整场逐帧重现。发行构建以及其他编号未验范围不包含在本次验收内。

## 移动撤销

### 实现范围

复用原有撤销按钮和移动流程，撤销记录统一由 `BattleManager.MoveUndo` 持有，鼠标确认移动与程序化玩家移动共用付款、导航提交及到达确认入口。只保留当前行动段内最近一次已完成的纯移动；再次移动覆盖旧记录，成功撤销立即消费记录，因此允许反复“移动—撤销”，不允许连续撤销两次。

快照保存付款前位置、朝向和实际 AP，并记录付款后 AP、对象初始化版本、导航终点、规则抽样版本以及参战者资源/状态的一致性信息。撤销按原值恢复 AP，不按当前费用配置重新计算；弹药、能量及其他单位资源必须保持一致，不替它们回滚。使用 NavMesh 的过滤和 Warp 同步导航，原位置不可用、被占用或状态已变化时拒绝退款。

### 失效边界

- 其他动作成功提交 AP 付款，包括固定费用、装填、技能、道具、警戒和模因换装，立即销毁旧记录；付费后麻痹取消或散热伤害也不能保留旧撤销。确认前被拒绝且未付款的命令保留原记录。
- 警戒/夹击反应排队即失效，即便反应最终取消或没有造成掉血。有效伤害、生命变化、旧 Buff 增减/来源变更、精确状态施加/解除、治疗区到达和场景交互均使记录失效；其他参战者的位置、资源或状态变化也由一致性校验拒绝。
- `BattleRandom` 抽样版本只递增；发生规则抽样即失效，麻痹成功通过后也不能撤销来反复尝试。撤销不恢复 Unity 全局随机状态，避免重投或回滚共用随机序列的表现/剧情。
- 在途、导航提交失败、超时、偏离终点、死亡、初始化复用、交棒、战斗停止及聚能行动段退出时不能撤销。普通回合与聚能额外行动段各自隔离，进入选人和退出额外行动清除记录。
- 保留现行自动交棒规则：最后一点 AP 用完并交棒后没有撤销窗口，不跨回合恢复。暂停时暂时禁止执行，恢复后没有其他变化则仍可撤销。
- 撤销取消当前选择/移动预览，只刷新交互和 Idle 表现，不调用 `StopMove`，不重放治疗区、到达效果或掩体特效。自动重选当前行动者保留本段快照，真正交棒仍显式清除。

上述不可逆边界是按开发计划中“由实现确认”的要求采用的保守实现，不新增整轮回滚或重投规则。正式场景的 `dragMove` 当前均为 0；未启用的直接拖动瞬移旧分支不新增撤销支持。

## 战斗时间控制

### 实现与配置

- 右上角双箭头和齿轮并排。快进使用 Toggle，1x 为浅色，3x 为金色，同时显示倍率文字；图标直接绘制，不依赖字体符号或新位图。
- UIManager 的 `fastForwardKey` 默认 `Space`，`None` 禁用；`fastForwardHoldThreshold` 默认 0.25 真实秒数。修改绑定应避开 Esc 暂停及现有功能键。旧结束回合按钮原绑定空格，但战斗初始化已禁用；快进在 EventSystem 前清除选中对象，防止同一次空格同时触发 UI Submit；输入框输入期间不响应。
- 短按在松手时切换。达到阈值后临时开启3倍速，松手恢复按下前状态；原本已为3倍速时，长按结束仍保留3倍速。失焦、丢失松手状态或窗口占用输入会取消本次按压并恢复；战斗停止时统一回到1x。
- TimeManager 优先级为暂停→命中停顿→战斗倍率。命中停顿不乘3，持续时间按真实秒数，在显式暂停期间冻结。恢复时保留当前快进选择，物理步长随有效倍率恢复。
- 齿轮使用 BattleScene.prefab 引用的原 SettingPanel.prefab，已有设置实例时复用；窗口通过 ActivePause 独立持有暂停。战斗实例启用原关闭按钮并适配尺寸，关闭或 Esc 返回后保留原快进状态；不改 AVG 场景及原设置 prefab。
- 普通行动、导航、AI、聚能与速度调度沿用战斗缩放时间。按钮反馈、血条拖影、跳字、通知、面板和页签表现使用真实时间；转场原有真实时间计时保持不变。快进状态不进入全局设置或存档，胜败、离场及时间管理器停用时清除。
