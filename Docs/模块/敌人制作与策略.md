## 制作流程

更新：2026-11-05。适用 Unity 2021.3.23f1、Odin、uGUI。面向开发者，记录从现有敌人预制体制作一个新 `EnemyController` 棋子的完整流程；也可整篇作为提示词使用。关联[当前开发计划](../开发计划.md)；原始[B36–B39任务定义](../验收和结果.md)已归档。

本文区分已确认规则、用户授权的临时数值和未定需求。新敌人的缺失数值不得从方尖碑示例自动套用；已有授权在其范围内执行，未授权内容保留待确认。方尖碑 B36–B38 已接入，当前配置见下方“6. 方尖碑当前正式示例”，不再作为未实现示例。

### 3. 数据权威性：哪些在 SO，哪些在预制体

复制预制体后最容易出错的是“改了预制体数值但运行时被 SO 覆盖”，或“以为 SO 能配所有数值”。当前实际规则如下：

| 数据 | 配置位置 | 运行时行为 |
| --- | --- | --- |
| `pieceID` | 预制体根节点 `PieceController.pieceID` | `PlayerController.Init` 用它从 `BattleManager.pieceDataListSO` 查找 `PieceData`；重复 ID 只会取列表中第一个 |
| 名称、生命、行动力、移动范围、速度、弹药、能量、暴击/闪避、元素、掉落、被动、词条身体/标签、成长、行动条头像 | `PieceDataListSO` 的 `PieceData` | 敌人初始化时 `SetEnemyData` → `SetData` 覆盖；1 级使用基础值，再叠加 `levelGrowth` |
| 通用 `ATK`、`CON`、嘲讽值 | 预制体 `UnitAttrCenter` | `SetData` **不写**这三项；`SetEnemyData` 会把预制体值作为基础保存，再按成长增加 |
| 分类型攻击 `attackDic`、分类型护甲 `_armorDic` | `PieceDataListSO` | 只覆盖显式配置的键；未配置的键保留预制体 `UnitAttrCenter.attr` 的值 |
| 最大生命/行动力/移动/弹药/能量/暴击/闪避/元素 | `PieceDataListSO` | `SetData` 总是覆盖预制体同名值 |
| 回合速度 | `PieceData.speed`；预制体 `turnSpeedOverride` | `turnSpeedOverride > 0` 时覆盖 SO；新敌人通常置 0 |
| 等级 | 预制体 `EnemyController.level` | 默认 1；成长由 SO 的 `levelGrowth` 决定 |
| AI 策略、是否激活、导航、死亡是否保留 | 预制体 `EnemyController` | `enemyAIType`、`isActived`、`navigate`、`deadNotDelete` |
| 显示帧、精灵渲染器、阴影、高亮 | 预制体 `PieceDisplay` 与子物体 | 运行时表现数据，不在 SO |
| 正式头顶读数、状态与样式 | `BattleOverheadStatusLayer` + `Resources/UI/PieceOverheadStatus.prefab`；UIManager可指定Variant | 敌我共用、无头像；布局在prefab调整，不在刷新时重建 |
| 旧血条与受击预览绑定 | 预制体 `EnemyCanvas` 嵌套实例 | 保留既有引用；旧血条/Buff根由共享层隐藏，仍承担兼容及预览数据，不是正式外观编辑入口 |
| 碰撞体、导航半径/速度/高度 | 预制体 `BoxCollider`、`NavMeshAgent` | 按体型调整；SO 不覆盖 |
| Tag/Layer | 预制体根节点 | 敌人使用 `Piece` 标签、Layer 11（以现有敌人为准） |
| 技能库、近战/远程技能 ID、初始主动技能 | `PieceDataListSO` | 设置了 `skillLibrary` 时按 ID 查库；为空时回退旧 `meleeAtk`/`rangedAtk`/`skillPacks` |
| 技能特效、弹道、动画索引、音效、MP、AI 用途 | `SkillPack` | `skillVFXType`、`bulletVFXType`、`animationIndex`、`skillSound`、`enemySkillRole` |
| 永久词条免疫 | `PieceData.permanentMemeImmunities` | B37已接入；与MemeUnitState本场抗性分开，Init/重开不清空。方尖碑配置1005；光环及屠龙术联动见[验收](敌人制作与策略.md) |

补充：

- 预制体上的 `_pieceData` 是 `[SerializeField] [ReadOnly]` 快照；运行时会被 `Init` 传入的 SO 数据替换。不要用修改这份快照来代替 SO 配置。
- SO 是 Odin `SerializedScriptableObject`，请在 Inspector 中编辑；直接手改 `.asset` 文本可能只改到 Unity 的 YAML 副本，实际 Odin 数据不生效。文件中同时存在 YAML 的 `pieceDataList`/`skillPacks` 副本，可能是旧的（例如 `PieceDataListSO` 的 YAML 仍显示旧内嵌攻击，而 Odin 数据已改为 `skillLibrary` + 技能 ID），不要用文本副本判断实际配置。
- 预制体 Enemy00 使用 1000，但 SO 中没有 1000 条目（复制 Enemy00 后必须改号）；方尖碑已占用1010。当前编号须从 Inspector/Odin 实际目录读取，不能把本文示例当作可用编号表；新敌人取号前检查目录与现有预制体，禁止复用1010。

### 4. 标准制作流程

#### 4.1 选择源预制体并复制

优先复制“同阵营、同体型、没有一次性特殊死亡/召唤逻辑”的敌人。当前 `Assets/Prefab/Battle/Enemy/` 下：

| 预制体 | `pieceID` | SO 名称 | AI 基础策略 | 备注 |
| --- | --- | --- | --- | --- |
| Enemy00 | 1000 | SO 中没有 1000 条目；显示资源前缀 PC03A | 旧值 1（不在当前枚举中） | 带 `SelfHeal`，场景中仍有实例；复制后必须改为新 ID、新增 SO 条目，并清掉旧的回合事件 |
| Enemy01 | 1001 | 打印机 | 混合型 | |
| Enemy02 | 1002 | 训练无人机 | 射击型 | |
| Enemy03 | 1003 | 杜伯安 | 技能型 | |
| Enemy04 | 1004 | 军械无人机 | 混合型 | |
| Enemy05 | 1005 | 黑衣人 | 技能型 | 同阵营黑衣人，适合作为方尖碑的复制源 |
| Enemy06 | 1006 | 地效车 | 特殊型 | 非人形载具结构 |
| Enemy10 | 1010 | 方尖碑 | 低防射击（临时） | 带 `ObeliskAura`/`BarrierEmitter`，护盾优先；永久免疫1005；Draft保持停用 |
| Enemy07/08 | 1007/1008 | 模因中毒者 1/2 | 射击型/混合型 | |
| Enemy09 | 1009 | 仲裁者 | 混合型 | |
| Enemy11 | 1011 | 自爆无人机 | 混合型 | 含自爆/死亡逻辑，除非新敌人也需要，否则不要作为源 |

操作：

1. 在 Project 窗口复制源预制体，改名 `EnemyXX`，放在 `Assets/Prefab/Battle/Enemy/`。
2. 保留根节点的核心组件：`BoxCollider`、`UnitAttrCenter`、`PieceDisplay`、`EnemyController`、`NavMeshAgent`，以及 `EnemyCanvas` 嵌套实例。
3. 保留/检查子物体：棋子精灵渲染器（`PieceDisplay.pieceSpriteRenderer`）、阴影、高亮、`EnemyCanvas`。`CardGameUI_13` 等旧装饰若不需要，删除并清理引用。
4. 复制后检查所有 `UnityEvent`：`OnInit`、`OnTurnStart`、`OnTurnEnd`、`OnHurt`、`OnDead`。源预制体上的 `SelfHeal.FullHp`、自爆、召唤等回调会跟着复制；不需要就清空，避免新敌人每回合自动满血或死亡时爆炸。
5. 若复制 Enemy10，还要按新敌人需求清理 `ObeliskAura`、`BarrierEmitter`、`initialSkillIds`、`permanentMemeImmunities` 和身体/标签，避免继承方尖碑的专用机制。不要只清 UnityEvent。
6. 复制后内部引用通常仍指向副本自身；一旦替换/重命名子物体，必须重新绑定 `pieceSpriteRenderer`、`enemyCanvas`、`unitAttrCenter`、`hightlightEffect`、`rangeUI`。

#### 4.2 重绑显示资源（PieceDisplay）

`PieceDisplay` 的字段与状态对应关系：

| 字段 | 播放状态 | 说明 |
| --- | --- | --- |
| `idleSprite` | `Idle` | 循环；空列表会停在当前帧 |
| `moveSprite` | `Move` | 循环，播放速度为普通帧率的 2 倍 |
| `meleeSprites` | `Attack` | 近战普攻；`PlayAction` 在序列中点释放命中 |
| `rangeSprites` | `Shoot` | 远程普攻 |
| `dodgeSprite` | `Dodge` | 空时回退 `idleSprite`；统一播放 1 秒并带横移 |
| `hitSprite` | `Hit` | 受击一次性 |
| `deathSprites` | `Death` | 死亡一次性；结束后走掉落/回收/胜负流程 |
| `skillSpriteList` | `Skill` | 外层每个元素是一个技能组；`SkillPack.animationIndex` 选择组 |

注意事项：

- 编辑器自动加载按钮（Inspector 的“测试加载图片”）只认 `<pieceName><suffix><n>.png`，序号从 1 开始且不补零；技能帧只认 `<pieceName>skill<组>-<帧>.png`。新素材若是 `INST1idle0000.png` 这类四位补零命名，自动加载找不到，必须手工按顺序绑定，或先统一改名。
- `skillidle`、`skillover` 目前没有独立字段。若持续护盾引导需要“引导循环/结束”动画，先确认是在 `skillSpriteList` 中合并，还是扩展 `PieceDisplay`；不要假设已有字段能播放。
- 绑定后检查精灵渲染器的缩放、位置、Sorting Layer/Order、翻转和阴影；`PieceDisplay` 只负责换帧，不负责自动适配体型。
- 记录实际使用的帧数。方尖碑当前素材：idle 6 帧（0000–0005）、move 5 帧（0000–0004）、skill 12 帧（0000–0011）、skillidle 6 帧、skillover 9 帧、hit 2 帧、death 10 帧。

方尖碑当前正式绑定（已接入；新敌人须单独确认动画规则）：

- `idleSprite`：`INST1idle0000`–`INST1idle0005`
- `moveSprite`：`INST1move0000`–`INST1move0004`
- `hitSprite`：`INST1hit0000`–`INST1hit0001`
- `deathSprites`：`INST1death0000`–`INST1death0009`
- `skillSpriteList[0]`：`INST1skill0000`–`INST1skill0011`（或按技能拆成多组）
- `meleeSprites`/`rangeSprites`：方尖碑经临时战斗配置授权，当前都复用12帧 `INST1skill`；这不是其他敌人的默认规则。
- `skillidle`/`skillover` 未接入独立引导状态。B37是回合入口被动光环；B38使用一次施放动画，护盾持续/破坏由独立实体播放，不要求来源持续引导。
- `PieceController.Init` 会调用 `PieceDisplay.ResetForReuse`，停止旧动画和淡出，恢复首次记录的美术透明度；复用时不要另加延迟回调重设颜色。

#### 4.3 更新预制体数值引用

复制后逐项检查：

1. `PieceController.pieceID` 改为新 SO 条目的编号；这是运行时加载数据的唯一入口。
2. `EnemyController.level` 默认 1；`enemyAIType` 选择 [敌人策略配置](敌人制作与策略.md) 中的枚举；`isActived` 按关卡初始状态；`navigate` 按是否需要导航；`deadNotDelete` 按死亡后是否保留尸体。
3. `PieceController.turnSpeedOverride` 新敌人置 0，使用 SO 的 `speed`；只有需要实例级速度覆盖时才填正数。
4. `UnitAttrCenter`：
   - 同步 `_maxHealth`、`_maxMovePoint`、`_moveRange`、`_maxAmmoCount`、`critRate`、`critDamageRate`、`elementType` 等回退值，使预制体在未 Init 时也可读；运行时仍以 SO 为准。
   - 通用 `ATK`、`CON`、`_tauntValue` 以及未在 SO 配置的分类型攻击/护甲，必须直接在这里配置；它们不会被 SO 覆盖。
   - `hpBarFill`/`hpBarUI` 若使用 `EnemyCanvas`，按现有敌人保持为空或指向 Canvas 内的组件，不要留下指向旧敌人的引用。
5. 内部引用：`pc`、`pieceDisplay`、`enemyCanvas`、`hightlightEffect`、`rangeUI` 全部指向副本自身；复制后打开 Inspector 逐个确认没有 `Missing`。
6. 体型适配：
   - `BoxCollider` 的 `size`/`center` 要覆盖实际可见范围，避免点选/遮挡异常。
   - `NavMeshAgent` 的 `radius`、`speed`、`height`、`baseOffset` 按体型调整，并在目标场景 NavMesh 上测试。
   - `EnemyCanvas` 的世界位置/缩放按新体型调整，避免血条、受击信息、Buff 图标埋进模型或飘得太高。
   - 根节点保持 `Piece` 标签、Layer 11、`isPlayerPiece = 0`。

#### 4.4 在 PieceDataListSO 添加棋子数据

在 Inspector 中打开 `Assets/ScriptableObjects/PieceDataListSO.asset`，在 `pieceDataList` 添加元素：

| 字段 | 说明 |
| --- | --- |
| `pieceId` | 未占用编号；预制体 Enemy00 用 1000（SO 无该条目），SO 已有 1001–1009、1011、2001 |
| `pieceName` | 显示名，如“方尖碑” |
| `memeBodyType` | 机械/生物；方尖碑按机械无人机配置 |
| `memeTargetTags` | 如“黑衣人”；屠龙术要求目标具备该标签 |
| `maxHealth` / `maxMovePoint` / `moveRange` / `speed` | 1 级基础值 |
| `turnPortrait` / `turnPortraitIsFullBody` / `turnPortraitFraming` | 行动条头像；可留空回退立绘或棋子精灵 |
| `attackDic` | 分类型攻击力；未配置的键使用预制体 `UnitAttrCenter.attr` |
| `_armorDic` | 分类型护甲；伤害类型映射：动能=`Melee(1)`、热能=`Ranged(2)`、火种=`Electric(3)` |
| `maxAmmoCount`、`evasionRate`、`critRate`、`critDamageRate` | 战斗数值 |
| `elementType` | 元素属性 |
| `skillLibrary`、`meleeSkillId`、`rangedSkillId`、`initialSkillIds` | 统一技能库；设置后按 ID 解析，旧内嵌字段不再参与攻击解析 |
| `skillPacks`、`meleeAtk`、`rangedAtk` | 旧格式，保留兼容；当前敌人条目多数已改用 skillLibrary + 技能 ID，实际以 Inspector/Odin 数据为准 |
| `dropItemList`、`dropRate` | 掉落 |
| `passiveSkillTypes`、`attrDic`、`orderProfiles`、`innateMemeIds` | 按需 |
| `levelGrowth` | 只填写已确认或明确授权的成长；默认填充工具不是必做步骤 |

补充：

- `PieceData.MeleeAttack`/`RangedAttack` 在 `skillLibrary != null` 时只查技能库；如果新敌人配置了技能库却忘了填 ID，攻击会变空，不会回退旧字段。
- `levelGrowth` 的“为敌人填充默认等级成长”只是编辑器默认值，不是策划确认值；未确认成长曲线时保留为空，避免悄悄引入未批准数值。
- 方尖碑的临时战斗数值和光环/护盾规则已分别获用户授权/确认，见下方“6. 方尖碑当前正式示例”；新敌人仍需自己的数值授权，不能照搬。默认成长填充会遍历整个目录，不能为了新增一名敌人批量修改其他敌人。
- 添加条目后确认 `BattleScene.prefab` 中 `BattleManager.pieceDataListSO` 仍指向 `Assets/ScriptableObjects/PieceDataListSO.asset`。

#### 4.5 配置技能、动画与特效

优先在独立或已有 `SkillPackListSO` 登记技能，用 `skillLibrary`、`meleeSkillId`、`rangedSkillId`、`initialSkillIds` 绑定。`skillId` 是稳定标识，显示名称变化不应换 ID。库存在但 ID 缺失时不会回退旧内嵌字段；新敌人不要继续扩展旧 `meleeAtk`/`rangedAtk`/`skillPacks` 格式。

每个 `SkillPack` 检查：

- `target`、`rangeType`、`rangeValue`、`reachKind`、`layerSkill`；范围、阵营与跨层规则由共用查询处理。
- `attackPacks`、`atkTimes`、`buffPacks`、`skillEffects`、`additionalEffects`；多段/多次攻击不可误配为重复施放。
- `enemySkillRole`：Auto、RangedAttack、MeleeAttack、Healing、RangeBarrier。标记用途不等于实现技能；群体护盾还需发射器、实体及对应 `SkillEffect.RangeBarrier`。
- `mpCost`、`consumeItems`、`animationIndex`、`skillSound`；动画索引须落在 `PieceDisplay.skillSpriteList` 范围内。
- AP读数/可支付判断/扣费统一使用 `UnitAttrCenter.GetSkillAPCost`；当前通用技能4AP，群体护盾按已确认规则2AP。`SkillPack` 没有单独AP字段，不要把 `mpCost` 当AP，也不要为一名敌人修改全局技能费用。

特效按实际类型接入：

| 类型 | 资源与入口 | 生命周期 |
| --- | --- | --- |
| 普通短效/弹道 | 按现有资源选择 `ItemType`，在 `ObjectPoolSO.itemPrefabDic` 绑定，再由 `skillVFXType`/`bulletVFXType` 或专用效果引用 | 沿对象池/`LifeTime`/现有弹道回收；需要时才制作Animation/Animator |
| 可攻击的范围护盾 | `BarrierEmitter.barrierPrefab` → `ObeliskRangeBarrier.prefab`，自身 `PieceDisplay` 播放 FIRESEEDbarrier 与 FIRESEEDbarrierD | 独立耐久、来源生命版本及死亡/禁用/重开清理；不额外新增ObjectPool类型或Animator |

有 `GenerateObject` 调用的特效必须登记；不使用某类特效时可保持 `ItemType.NONE`，但不能直接对 NONE 调用生成。不能为了“统一流程”强迫所有战斗实体进入同一个对象池。

方尖碑专用机制已实现：

- `ObeliskAura` 在普通回合开始治疗35%，不通过 `AutoHeal.stacks` 实现。旧AutoHeal固定15%，两者独立。
- `RangeBarrier` 是空间群体护盾；旧 `SlowingField` 仍是单体耐久、破盾当次全吸收，不能替代。
- 直接伤害走 `BattleManager.PieceSkill`/`DamageManager.ResolveSkillTarget`；预览使用同一公式和只读耐久副本。不要另写一套VFX碰撞扣血绕过拦截与来源上下文。

### 5. 常见陷阱

1. **只改预制体，没改 SO**：运行时 `pieceID` 查到旧数据，生命/护甲/技能全是旧的。
2. **只改 SO，没改 `pieceID`**：仍然加载旧条目，或 `GetPieceData` 找不到时报错。
3. **重复 `pieceID`**：`GetPieceData` 使用 `Find`，只会取第一个，后加的条目静默失效。
4. **手改 SO YAML**：Odin 数据在 `serializationData`，文本里的 `pieceDataList` 可能不是实际生效副本；用 Inspector。
5. **自动加载找不到序列帧**：`INST1idle0000.png` 这类补零命名不匹配 `<pieceName>idle1.png` 规则；手工绑定或统一改名。
6. **`skillidle`/`skillover` 没有入口**：`PieceDisplay` 没有这两个字段；不要假设绑定后会自动播放。
7. **护甲键写错**：热能=`Ranged(2)`、动能=`Melee(1)`、火种=`Electric(3)`；写反会导致伤害类型不匹配。
8. **`ATK`/`CON`/嘲讽以为在 SO**：它们不在 `SetData` 覆盖范围内，必须在预制体 `UnitAttrCenter` 配置或通过 `attrDic` 修改。
9. **`skillLibrary` 设置了但 ID 为空**：攻击解析不会回退旧字段，直接变空；要么完整迁移，要么先用旧字段。
10. **复制后保留旧 `UnityEvent`**：源敌人的 `SelfHeal.FullHp`、自爆、召唤会跟着复制，导致新敌人行为异常。
11. **`turnSpeedOverride` 非 0**：会覆盖 SO 的 `speed`，看起来像“SO 速度不生效”。
12. **只调整旧`EnemyCanvas`外观**：正式读数来自共用头顶模板；应调整模板/变体偏移并检查精灵边界，旧Canvas只维护兼容引用。
13. **Layer/Tag/`isPlayerPiece` 错**：点选、阵营、伤害和 AI 目标关系都会异常。
14. **对象池短效只建prefab，没进`ObjectPoolSO`**：`GenerateObject`返回null并报错；独立护盾实体则检查发射器的正式prefab引用。
15. **把35%写进`AutoHeal.stacks`**：AutoHeal固定15%；方尖碑已由`ObeliskAura`实现，不应再加一份旧AutoHeal冒充光环。
16. **把单体`SlowingField`当群体护盾**：它没有空间边界且溢出规则不同；方尖碑已有`RangeBarrier`，不要重复实现。
17. **忘记 `AIController.pieces`**：场景里看得见，但不会初始化/行动；波次和迷雾只负责激活。
18. **`BattleManager.pieceDataListSO` 为空**：运行时 `GetPieceData` 直接空引用；确认 `BattleScene.prefab` 的引用。

## 策略配置

在敌人棋子的 `EnemyController` 上配置以下内容。原 `enemyAIType` 字段和旧枚举数值保留，显示名称为基础行动策略；旧预制体可继续使用旧模式，也可在 Inspector 中改选下面带策划编号的新模式。所有非 Boss 的普通模式默认具备治疗优先和残血撤离逻辑。

### 策划通用行为模式

| 编号与枚举 | 索敌 | 行动 |
| --- | --- | --- |
| 1 `NearestAdaptive` | 最近目标；同时有多个能立即普攻的目标时，改选血量较弱者 | 目标在远程射程内且距离大于其一半、有弹药时远程攻击，否则接近并近战；不为此模式主动装填 |
| 2 `WeakestDefenseShooter` | 场上防御力最低者 | 优先远程攻击；受有效掩体遮挡时先移动到无遮挡射击点；射击后规避半射程内的所有威胁目标 |
| 3 `DamageHunterAOE` | 对自身造成最多历史伤害者 | 距离大于最远攻击射程一半时远程，否则近战；可命中多个目标时优先 AOE 技能或 AOE 普攻 |
| 4 `DamageHunterRangedSkill` | 对自身造成最多历史伤害者 | 可群攻或有低血量技能目标时优先技能；否则距离大于半最远射程时有 1/3 概率尝试远程技能，未触发/不可用时按远近选择普攻 |
| 5 `DamageHunterMeleeSkill` | 对自身造成最多历史伤害者 | 距离严格小于半最远射程时有 1/3 概率尝试近战技能，否则按远近选择普攻 |
| 6 `DamageHunterMeleeOnly` | 对自身造成最多历史伤害者 | 只使用近战攻击，不射击、不装填；也不会用远程攻击引爆桶 |
| 7 `FragileMeleeOnly` | 最低最大生命值或最低防御力 | 只使用近战攻击 |
| 8 `HealingSupport` | 回复优先，普通索敌配置作为进攻兜底 | 移动范围内自身/存活友军低于 50% 血量时优先回复，必要时移动后施放；没有合法回复机会时正常行动 |
| 9 `WoundedRetreat` | 保留索敌配置 | 启用通用残血撤离；该逻辑也默认叠加在其他普通模式上 |

模式 1～7 自带的索敌规则优先于独立 `targetStrategy`。未受到过伤害时，“最高历史伤害”回退到最近目标；历史伤害相同时也优先最近目标。最远攻击射程取近战、远程和攻击技能中的最大值，不计回复技能。

“模式1·范围内血量优先级”提供当前生命值/最大生命值两个中文枚举选项；“模式7·弱者判定”提供最大生命值/防御力两个选项。防御类型默认比较热能（远程）护甲，可通过“防御力比较类型”改成动能或火种。

### 治疗与撤离的共通配置

- `prioritizeHealing`：默认开启；模式 8 即使关闭该开关也会尝试回复。回复阈值 `healHealthRatio` 默认 0.5，严格低于阈值才触发。每名敌人每个个人回合最多主动施放一次回复，防止延迟治疗在尚未生效时被反复释放。
- `isBoss`：Boss 豁免自动撤离。请给 Boss 预制体勾选该字段。
- `retreatWhenLowHealth`：默认开启；`retreatHealthRatio` 默认 0.3，严格低于阈值才撤离。先完成一次当前能执行的攻击，再沿实际导航路径向场地外侧移动；不会为攻击追击、绕路或先装填。无攻击机会时直接撤离，到边缘后停止移动。
- `executeHealthRatio`：模式 4 的“低血量目标”技能优先阈值，默认 0.3。

回复优先于紧急攻击/撤离；已有移动后攻击计划可被回复或残血撤离打断。无有效路径、被束缚或行动点不足时不强行移动。特殊型 `RetreatWin` 保留关卡专用撤离，不叠加通用逻辑。

技能的“敌人 AI 技能用途”是带中文 LabelText 的 `EnemySkillRole` 枚举：自动识别、远程攻击技能、近战攻击技能、回复技能。自动识别会把治疗区、自动治疗 Buff 判定为回复；其他技能根据相对近战射程区分远近。回复技能仍须配置真实回复效果及友军/自身/区域目标规则，标注用途不会凭空生成治疗效果。

模式 2 的引爆优先仍受 `attackExplosives` 开关控制，默认关闭；对具备此能力的敌人单独开启。攻击完成后先处理规避，再考虑下一次引爆/射击，避免连续攻击饿死移动。

### 两个独立部分

| 配置 | 可选内容 | 行为 |
| --- | --- | --- |
| 索敌策略 `targetStrategy` | 标准仇恨 | 保留原算法：嘲讽值 + 最近目标 1 分 + 造成最多历史伤害的目标 2 分；同分沿用原顺序 |
| 索敌策略 | 最近目标 | 忽略仇恨，追逐离自身最近的有效玩家棋子 |
| 索敌策略 | 最低当前血量 | 忽略仇恨，选择当前血量最低的有效玩家棋子；按血量绝对值计算 |
| 基础行动策略 `enemyAIType` | 射击型 | 远程攻击，射击后尝试撤离，范围不足则接近 |
| 基础行动策略 | 技能型 | 优先可用攻击技能，无技能可用时按混合型行动 |
| 基础行动策略 | 混合型 | 优先近战，再考虑远程，最后接近目标 |
| 基础行动策略 | 特殊型 | 沿用关卡 `RetreatWin` 撤离逻辑；配置该类型需提供对应组件与目标点 |

死亡、隐藏、不可被攻击的玩家棋子不参与索敌。最近和最低血量策略同值时选择列表中的第一个有效目标。仇恨指示及移动预览使用同一套索敌规则。

### 条件切换

`strategyRules` 是从上到下检查的规则列表，第一条满足全部条件的启用规则生效。每条规则同时提供新的 `targetStrategy` 和 `actionStrategy`。

支持的条件：

- 自身血量比例不高于 `healthRatio`，例如 `0.3` 表示当前血量不超过最大血量的 30%。
- 可索敌目标数量不多于 `count`，只统计存活、显示且可攻击的玩家棋子。
- 存活且激活的友军数量不多于 `count`，不包含敌人自身。

示例：基础配置为标准仇恨 + 混合型；添加规则，自身血量比例不高于 0.3，切换为最近目标 + 射击型。也可以再添加一条规则，当可索敌目标数量不多于 1 时改用最低血量 + 技能型。两个规则同时满足时，列表靠前的规则生效。

每次规划时重新评估状态；条件解除后恢复基础策略或下一条匹配规则，不永久锁定阶段。空条件规则不触发。切换策略后废弃旧的移动后攻击计划；未发生切换且未触发紧急回复/撤离时继续保留已经承诺的计划。切换后的行动策略也可以选择新的编号模式，此时其内置索敌规则生效。

### AOE 攻击选点

`maximizeAOETargets` 默认开启，适用于普通近战、远程和主动技能。以技能的正式目标规则判断是否多目标：`EnemyAll` 或 `All`。`Enemy`、`FarthestEnemy` 等单目标技能仍保持单目标规则。

比较目标位置、两目标中点、群体中心，以及圆形覆盖交点；扇形和弧形还比较每 5 度的朝向。所有候选落点受施放距离限制，并使用 `SkillTargeting.Query` 计算实际命中目标，沿用层高、存活、阵营和范围形状规则。Nova 始终以自身为中心。

优先命中更多敌对目标；同数量时优先包含索敌目标，再减少可能命中的友军。允许爆炸半径命中施放距离外的目标。移动后和正式出手前按新位置重新计算选点，攻击动画、范围预告和最终命中共用该落点。这是候选采样优化，不保证连续空间中的数学最优解，也不会为提高命中数额外消耗移动行动力。

### 利用爆炸物

敌人的 `attackExplosives`（Inspector 名称：允许攻击爆炸物）默认关闭。只对希望具备该能力的敌人或敌人预制体开启。

开启后，敌人在正常行动规划中会优先检查场景内注册的普通爆炸桶和电浆爆炸桶。桶必须存活、显示、尚未引爆，且本次爆炸或电浆脉冲能伤害至少一个玩家。检查使用桶自身的爆炸半径、碰撞层、技能阵营/层高、伤害预览和屏障规则，不只比较玩家到桶的距离。

敌人只选择当前攻击距离和范围形状能命中、能造成正伤害、且资源足够的攻击。射击型用远程攻击，技能型优先技能，混合型优先近战再远程。空弹匣时需要保留装填和攻击的行动点；特殊型继续专用关卡行为。多个可用桶优先选能影响更多玩家的桶，再选离自身更近的桶。没有可用桶则继续原来的索敌与行动方式，不为引爆桶额外绕路。

攻击环境目标时只在该次技能副本中允许命中桶，不修改技能资产，不让单目标攻击变成群攻。桶仍通过原来的受击/死亡事件触发爆炸或电浆脉冲；普通桶生命较高时可能需要多次攻击。场景中的桶需保留原有的受击/死亡事件绑定。

普通桶死亡后的延迟爆炸使用运行时技能副本继续结算，避免被“施法者死亡”检查拦截。普通角色的死亡依然会中止攻击。

### 结算与预览可靠性

`DamageManager.ResolveSkillTarget` 统一拦截技能/普攻/爆炸的直接伤害；`BattleManager.AbsorbRangeDamage` 按射线进入球面的距离由外到内处理嵌套护盾，同距沿注册顺序处理。独立扣耐久保留根行动，不触发内部目标受伤/击杀事件。

预览使用真实结算公式，在耐久副本上模拟先前 AOE 目标和多段伤害，不修改真实耐久、生命或随机状态。先前目标可能未命中时，最小伤害分支保留护盾耐久。范围 UI 提供当前目标顺序的只读入口，回调不递归查询；持续刷新预览以响应耐久和目标顺序变化。

来源生命版本变化、死亡或禁用后，护盾立即失去拦截资格，随后清理实体。聚能中的普通外部攻击延期结算；聚能破盾立即更新逻辑耐久，冻结破坏首帧，退出后按原队列播放，死亡动画纳入动作等待后再交棒。

## AI跨层选梯

开启敌人的 `navigate` 后，普通策略及编号策略均将目标位置传入 `MapController.TryGetLadder`。楼梯需要启用、允许交互且配置 `upPos` / `downPos`；入口必须在当前层，出口必须在目标层，两端分别有完整路径。当前层与目标层沿用一米高度差判定。无楼梯或路径不完整返回false，由现有AI更新逻辑结束无法行动的回合，不启动移动或攀爬。

在场景 `MapController` 上配置三个非负权重（默认均为1）：

- `ladderApproachWeight`：当前位置到楼梯入口的路径长度。
- `ladderRemainingWeight`：楼梯出口到目标的路径长度。
- `ladderHeightWeight`：楼梯两端的高度差。

总代价是以上三项的加权和；相同代价保留列表中的先后顺序。每次决策重新查询，不缓存失效路径。路径查询沿用角色的Agent Type、Area Mask和区域寻路成本；最终楼梯排名使用折线路程的加权和，不是区域成本积分。

AI沿选中的入口路径移动，不使用随机接近点。入口路程不超过2米、NavMesh直线无阻挡且落点可达/未被其他角色占用时才尝试攀爬；落点保留原有水平偏移，仅允许0.1米吸附。扣费触发状态效果后再次查询，失效则不传送（已经结算的行动费用不退款）。传送成功才揭示目的层迷雾。玩家原有楼梯交互保持原实现。

场景前提与边界：入口/出口标记应位于可行走表面，Agent停止距离应小于2米，实体墙需要正确烘焙或Carving。查询不创建或重烘焙NavMesh，不修改导航包。当前选择单座直接连接当前层与目标层的楼梯，不自动组合多座楼梯绕经第三层；无此直连路线会明确失败。

本轮验证：`tmp/LadderNavigation/B05-20261029/` 中32项替身断言通过，直接编译MapController并提取当前AI入口及LadderArea提交方法；覆盖第一座不可达第二座可达、上下楼/错误层、无梯、断路、部分路径、稳定代价和权重、隔墙/落点检查、提交时失效及费用边界。Unity2021项目引用离线编译通过。替身不运行真实NavMesh、移动动画或碰撞，Play Mode及构建未执行，B05保持待验收。

真实场景复验：在两个已有导航层之间设置两座楼梯，阻断列表第一座入口，确认AI走第二座；分别移除全部楼梯、断开出口至目标路径、将目标移到第三层，确认交棒且不空耗攀爬AP；移动途中禁用楼梯或放置Carving障碍，确认下一次决策重选或失败；入口隔墙、出口被棋子占用时不传送；交换三个权重观察路径选择，并检查上下楼位置、迷雾和Console。
