# 模因与状态

优先使用配置目录、来源登记和统一生命周期接口；未定义词条继续禁用。显示状态不应触发施加、概率抽样或计时。

## 模因服务与扩展

当前实现提供模因配置、队伍解锁、双槽装配、四类来源合并、目标过滤、抗性与概率判定、只读预览、已有 Buff 效果和自定义效果接口。已连接正式技能结算、玩家与敌方夹击/警戒、插件内爆的反应标记。B10已接入细胞自毁/散热故障的精确状态、指定标签解除及散热恢复抗性，见[接入及验收](模因与状态.md)。本阶段不新增界面，也不实现混乱、逆转敌我等完整 AI 行为。

### 配置入口

在 Unity 资源创建菜单选择 Game/MemeCatalog，新建目录资源。把资源指定到 DataManager.memeCatalog，或仅指定 BattleManager.memeCatalog 覆盖当前场景。没有配置目录和模因来源时，现有战斗保持原有行为。

每个 MemeDefinition 使用发布后保持不变的正整数 id。重复编号、无效概率、空效果或无效枚举不能触发。未实现词条设 enabled=false，可作为无效果的禁用占位项。

| 字段 | 用法 |
|---|---|
| targetBodies | Biological、Mechanical 或 All；与伤害类型、阵营无关 |
| targetRelation | Hostile 默认只影响敌方；Friendly 影响友方（包含自身）；Any 不限制 |
| requiredTargetTags | 必须全部匹配 PieceData.memeTargetTags，区分大小写 |
| triggers | AttackHit 或 SupportResolved，可组合；没有伤害段的技能按支援事件处理 |
| requiresRecognitionSuccess | 要求技能开启现有模式识别且结算结果为成功/大成功，不自行额外掷骰 |
| chancePercent | 0至100的词条触发概率；Effects 内不再独立掷概率 |
| allowNetworkCrossType | 目标处于网络暴露时，生物/机械之间允许跨类型；不绕过剧情标签和免疫 |
| allowReactions | 默认关闭，夹击、警戒、插件内爆不会再次触发；需要时逐条启用 |
| effects | Buff 效果提交现有 BuffManager；Custom 效果由 handlerId 对应处理器执行 |

在 PieceData 上填写 memeBodyType 与 memeTargetTags。未配置的新资产仍为None，不推测身体类型；B12已按用户确认完成现有17条记录的身体类型和黑衣人标签，详见[正式配置及界面验收](模因与状态.md)。All类型词条可作用于未配置身体类型的特殊对象，生物/机械专用词条不可。

已有 Buff 的 stacks 仍沿用旧含义：多数普通状态是持续回合，燃烧是强度，-1是永久。durationTurns/magnitude 仅供 Custom 处理器使用。不要用 Stun 直接代替“30%取消行动”的麻痹，也不要用现有 Overload 代替细胞自毁的精确数值；应在后续具体状态实现中处理。

### 解锁和装配

永久解锁保存于 PLAYERPROFILE.memeProgress；角色自由装配保存于 Player.memeSlots。普通新存档和缺字段旧存档通过默认构造获得空数据；显式写入 null 的数据在接入处按空集合处理，不自动解锁任何词条。

```csharp
var profile = GM.Ins.PLAYERPROFILE;
profile.memeProgress ??= new MemeProgress();
bool unlocked = GM.Ins.DM.TryUnlockMeme(memeId, out string error);

bool changed = MemeEquipment.TryEquipOutsideBattle(
    player, profile.memeProgress, GM.Ins.DM.memeCatalog,
    new[] { firstMemeId, secondMemeId }, out string error);
```

两个槽位都必须提交，0表示空槽。同一词条不能重复装配，必须已永久解锁且配置有效。输入数组会复制，不作为角色长期持有对象。战斗进行中免费入口拒绝操作。

```csharp
bool changed = BattleScene.Ins.BM.memeService.TryEquipInBattle(
    currentPiece, new[] { firstMemeId, secondMemeId }, out string error);
```

战斗内必须是当前可控、属于玩家参战列表的角色；动作进行中和外部程序接管期间不能通过此菜单入口操作。确认整套装配扣2AP，空槽替换同样扣费；无变化、非法、未解锁、超槽配置不扣费。调用现有 CostMP(int)，若行动被已有状态中断，遵循旧费用入口已扣AP不返还的行为，但不替换槽位。

暂不通过插件临时授予自由装配权限。插件的固有词条用 ComponentData.memeIds 自动提供；配方、成长或剧情需要永久授予时调用 TryUnlock。

### 词条来源与触发

| 来源 | 配置位置 | 占用自由槽位 | 需要永久解锁 |
|---|---|---|---|
| 自由装配 | Player.memeSlots | 是，最多2个 | 是 |
| 技能固有 | SkillPack.memeIds | 否 | 否 |
| 插件固有 | ComponentData.memeIds | 否 | 否 |
| 棋子固有 | PieceData.innateMemeIds | 否 | 否 |

来源在 BeginCombatAction 开始时读取，按编号升序合并；同一种模因多来源不叠概率。技能伤害各段结算结束后、附加状态和击退前，MemeService.ResolveTarget 处理存活目标；未命中、屏障阻挡和已死亡目标跳过。零伤害但有效命中的目标仍可触发。

每个 MemeActionContext 内，同目标同词条最多判定一次，概率失败和抗性抵抗也消耗这次机会；AOE 的不同目标分别判定。当前判定单位是一次 PieceSkill 调用。正常动画行动为其提供同一个上下文；直接调用 PieceSkill 的多次子结算如属于同一行动，须显式复用上下文：

```csharp
var action = battle.memeService.BeginAction(actor, skill, isReaction: false);
battle.PieceSkill(actor, targets, skill, targetPosition, memeActionContext: action);
```

插件或自定义效果产生的追加技能应使用 isReaction=true 创建上下文，避免将追加攻击当作普通主动行动。当前接口不限制自定义处理器任意调用其他战斗 API；处理器自身须避免无界递归。

### 网络暴露 抗性和预览

```csharp
target.MemeState.NetworkLinked = true;
target.MemeState.SetResistance(memeId, 50);
```

NetworkLinked 只是暴露状态，不改变棋子身体类型。抗性按词条保存，0为无抗性，100为免疫，值限制在0至100。概率判定先抗性后触发概率。棋子 Init 会 Reset 所有本场暴露与抗性；不在 OnDisable 时清理，以免临时隐藏或迷雾影响规则。

B13已将网络暴露改为按节点来源汇总。节点使用 `MemeNetworkNode.TryConnect(target)` / `Disconnect(target)`，重复进入幂等；范围模块应汇总同一目标的多个碰撞体，只在最后一个接触退出时解除。节点禁用/销毁释放自身连接，棋子死亡/Init/销毁及战斗结束清理旧连接；临时隐藏棋子保留连接。

旧 `NetworkLinked` 赋值兼容为独立手动来源：设为false只撤销手动来源，不覆盖节点。清除全部来源须调用 `ClearNetworkLinks()`；节点模块不要再写布尔开关。节点重启、重建或棋子重新Init后，由范围/交互模块重新登记，不自动恢复旧成员。详见[网络节点多来源与B13验收](模因与状态.md)。

```csharp
var attempts = battle.memeService.PreviewTarget(actor, target, skill, checkResult);
```

预览不掷骰、不记尝试、不施加效果、不发送 AttemptResolved。Outcome 表示是否满足门槛；ChancePercent 是抗性修正后的条件概率，只有 Eligible 时才表示可用触发机会，不包括技能命中率和模式识别成功率。未提供识别结果时，需要识别的词条返回 RecognitionRequired，不预测识别必成功。

所有实战词条判定结果可订阅 AttemptResolved；日志与界面可显示类型不符、标签不符、未通过识别、免疫、被抗性抵抗、概率未触发等原因。效果类型不支持时返回 UnsupportedEffect，不消耗随机也不会部分施加其他效果。

### 自定义效果接口

复杂词条通过 IMemeEffectHandler 接入：

```csharp
public sealed class ConfusionMemeHandler : IMemeEffectHandler
{
    public bool CanApply(MemeEffectContext context, MemeEffectDefinition effect)
        => /* 只读校验所需状态和行为服务 */ false;

    public void Apply(MemeEffectContext context, MemeEffectDefinition effect)
    {
        // 交给具体状态服务记录来源、持续时间及解除规则。
    }
}

battle.memeService.RegisterEffectHandler("confusion", new ConfusionMemeHandler());
```

上述代码是接口示意，不是已实现的混乱行为。CanApply 必须只读，Apply 不再判词条概率，也不得修改共享配置。重复 handlerId 注册返回 false，避免覆盖现有处理器。执行前会检查该词条全部效果是否具备可用处理器。

B10已自动注册cellular-self-destruction与heat-malfunction处理器，并通过TimedMemeDefinitions提供已确认配置模板；SkillPack.memeCureTags默认None，匹配标签的技能才解除新状态。MemeEffectContext.Action保存真实来源，预览为空。具体数值、回合快照、刷新、付费行动及恢复规则见[接入及验收](模因与状态.md)。B11已另行确认并实现麻痹、暴力、逆转敌我、屠龙术，注册paralysis、violence、inverted-allegiance、dragon-slaying；行为关系、AI接管、受伤解除、TrueShadow和恢复规则见[行为状态接入及B11验收](模因与状态.md)。未定义词条仍保持禁用。框架不改变现有识别时机、伤害公式和掩体。

## 双槽装配与正式目录

### 使用入口

- 战斗中：当前可操作角色的行动菜单新增“模因装配”。选择槽位，再点击词条；可清空当前槽。整套配置确认后支付一次2 AP。
- 战外：角色页面右上角“模因装配”，确认免费；战斗进行中从角色页面进入时仍走战内校验，不允许免费绕过。
- 词条列表展示解锁状态，详情展示目标身体/标签、施加概率、识别门槛、反应限制及当前装备/角色/技能/插件来源。详情支持滚动；槽位草稿不影响“当前来源”。
- 取消、右键、Escape、控制权丢失、死亡及离开战斗均放弃草稿。重复词条、未解锁/无效词条、无变化、AP不足、外部控制及其他入口更新配置会拒绝确认。

### 解锁、存档与接口

正式目录不会默认赠送解锁。现有进度保留，旧档缺失/空字段以空槽及未解锁显示；打开、浏览、预览及取消不会修复或写回存档。

剧情新增`UNLOCKMEME(1001)`等指令，由`DataManager.TryUnlockMeme(id, out error)`调用现有永久解锁接口；成长/配方也可使用同一入口。无效和重复解锁不修改进度。存档仍沿用既有保存流程，装配及解锁保存在`Player.memeSlots`、`PLAYERPROFILE.memeProgress`，没有另建存档格式或改动配方经济。

`MemeLoadoutPanel`只持有独立草稿和打开时的槽位快照，确认调用`MemeService.TryEquipInBattle`或`MemeEquipment.TryEquipOutsideBattle`。其他入口改变槽位后拒绝旧草稿覆盖。战内扣AP后的散热/麻痹中断沿现有规则保留已扣AP，但不提交装配；重复确认不会重复支付。

界面以运行时uGUI接入现有Canvas，沿用原字体，未重建现有角色页或战斗菜单预制体。`ClickManager`和行动展示流程在装配弹窗期间等待，关闭后由原流程恢复菜单。角色页旧选中标记可能是Unity空对象，`UITabController`改为显式判空后访问原生接口，避免打开真实页面时报错。

## 伤害状态

### 规则依据

用户已确认本次完整规则，定稿记录见[决策表B10补充](战斗规则.md)。只实现这两种新状态，不用旧Overload、Burn或SpontaneousMemeticAttack替代。

| 状态 | 门槛 | 持续/触发 | 解除/恢复 |
| --- | --- | --- | --- |
| 细胞自毁 | 生物；15%概率；沿现行目标过滤/网络例外 | 5个目标普通回合，回合开始扣最大生命10%并向上取整；移动范围乘0.8 | Vaccine或Medical；不自动增加恢复抗性 |
| 散热故障 | 机械；显式识别成功或大成功；沿现行反应开关 | 3个目标普通回合，成功扣正AP后、主动行动执行前扣最大生命10%并向上取整 | Update；自然到期/指定解除后本场同词条抗性至少50%，不累加、不降低更高值 |

两者都从下一个目标普通回合计时，普通回合结束减1。聚能额外行动不触发普通回合DOT、不减时，但付费主动行动触发散热故障。刷新重置持续时间、覆盖最新来源、不叠加强度；当回合旧快照失效。死亡、初始化、销毁和战斗清理不视为自然恢复；临时隐藏棋子保留状态及本场抗性。

### 业务入口

`BattleManager.timedMemeStatuses` 持有本场 `TimedMemeStatusService`。`MemeService` 自动注册 `cellular-self-destruction` 与 `heat-malfunction` 两个Custom处理器，不再要求场景挂额外组件。

正式目录在分配未占用的稳定编号后，可用以下模板创建词条；这里的编号由配置方提供，不在代码中硬编码占用目录编号：

```csharp
catalog.memes.Add(TimedMemeDefinitions.Cell(cellMemeId));
catalog.memes.Add(TimedMemeDefinitions.Heat(heatMemeId));
```

模板填写既定概率、身体类型、识别要求、5/3回合与0.1强度。Custom效果必须填写对应handlerId及上述持续/强度才能由处理器接受；无效配置返回UnsupportedEffect。目录仍由BattleManager或DataManager显式引用，角色装配/技能固有/插件固有来源沿原框架接入。没有目录或来源时不自行分配新能力；双槽界面和正式角色配置闭环继续属于B12。

技能新增 `SkillPack.memeCureTags`，默认None。配置指定治疗时填写 `Vaccine`、`Medical`、`Update` 或需要的组合，正式目标结算通过后才解除匹配状态。普通 `Heal` 保持回血语义。程序化解除可调用 `battle.timedMemeStatuses.TryCure(target, tags)`，返回实际移除数量，不赠送回血/AP。

### 时序与来源

- 速度调度在目标 `TurnStart` 事件前调用 `BeginNormalTurn`，旧Buff处理后调用 `ResolveTurnStart`，目标 `TurnEnd` 事件后调用 `EndNormalTurn`。聚能路径不调用这三项普通回合钩子。
- 每条状态独立保存剩余回合、强度、词条编号、施加者、来源类型和施加时的BattleActionContext。MemeEffectContext显式携带真实行动来源，公开ResolveTarget调用在没有全局作用域时也不会丢失根ID；预览仍不分配行动上下文。用状态修订号保护刷新，不混用Buff层数。重复调用同回合DOT不会重复扣血。
- 警戒确认原来仅执行旧OnAction而没有支付菜单显示的AP。本轮将 `CastOrder` 接入GuardOrder费用配置，保留只瞄准/取消不扣费，重复确认不再支付；致死或费用失败不建立指令。这是为了让实际警戒确认也经过已确认的付费主动行动状态入口。
- `UnitAttrCenter.CostMP(ActionType)` 在正AP扣费后触发精确主动行动钩子，Wait除外。`CostMP(int)` 保留原固定费用语义，不从整数猜行动类型；模因换装改用 `CostMP(cost, true)` 显式声明主动行动。失败校验/不足AP/眩晕/被束缚的移动不先扣状态伤害；零AP、待机和免费反应不触发新状态。
- 10%伤害直接走有来源的TakeDamage；细胞为Periodic、散热为ActionEffect，保留原施加者/技能/根行动。沿用现有生命反馈，不额外伪造一次普通命中或通知旧攻击被动。热故障行动前致死时费用入口返回false，原动作及尚未扣除的次级费用不再执行。
- 移动减幅由独立倍率计算，与旧Buff移动修饰相乘；刷新不反复减20%，解除不反向累加污染旧Buff。

| 屠龙术1.0 | 配置传入黑衣人标签；15% | 4个目标普通回合；禁止进攻及夹击/警戒；AI优先正常治疗或解控，否则远离原玩家单位威胁 | 仅TrueShadow；自然到期/指定解除登记本场同词条至少50%抗性，max不叠加 |

四种状态沿用B10普通回合快照、当回合刷新保护和聚能额外行动不减时规则。麻痹不拦截结束回合和免费反应。多个状态同时存在时，禁攻优先于逆转关系，逆转优先于暴力选敌，麻痹独立判定。保留现有身体门槛中的网络暴露例外和默认反应关闭规则。

暴力/逆转的受伤解除只认HpLoss>0；0伤、未命中、屏障全吸收和纯自伤不解除。Periodic、Collision和Component等外来伤害经统一生命入口处理。生命提交后、生命观察者与本次新模因施加前先移除旧状态，因此同次命中新施加的状态保留。死亡/重置/战斗清理不登记恢复抗性。

### 接入

- `TimedMemeDefinitions`提供四种模板；编号仍由正式目录分配，`Dragon(id, blackSuitTag)`要求配置提供标签，空标签使定义无效。`TimedMemeStatusService`记录持续、来源、刷新版本、解除标签和行为标志。
- `BattleRelations`统一行为视角的攻击/支援判断，不修改`isPlayerPiece`、队伍列表、角色所有者或胜负归属。SkillTargeting、技能实际结算、Buff过滤、夹击候选、警戒穿越和排队出手复查共用关系。
- `CanControlPiece`阻止玩家操作被接管角色。AI在普通敌人决策之前处理当前行为状态，玩家角色和敌人共用付费动作；动作失败/麻痹取消不会在同次决策继续尝试并额外扣费。普通回合和聚能均可接管；聚能请求/选人时暂停普通AI，额外行动中继续代管；恢复后按原角色控制方式继续。
- 禁攻在正常攻击费用、技能合法性、最终技能结算及反应入口拦截，已排队警戒也复查。辅助解控攻击同样受禁攻限制。
- AI从真实可用技能中选择标签匹配的解控或现有治疗，使用原AP/能量/道具费用。无指定治疗时，可用预计有实际伤害且非致死的单体普攻帮助原友军解除暴力/逆转，使用正常攻击费用，屏障全吸收时不选用。不会凭空授予治疗或免费移除状态。
- 屠龙术无可执行治疗/解控时，从可达导航落点中选择提高与玩家威胁最小距离的位置；无有效动作则结束当前行动，不空耗资源。

### 接入方式

在节点对象添加正式组件 `MemeNetworkNode`，由范围或交互模块登记目标：

```csharp
node.TryConnect(target);
node.Disconnect(target);
node.DisconnectAll();
```

- 同一节点对同一棋子重复连接幂等。多碰撞体目标由范围模块先汇总接触，仅在最后一个接触退出时调用Disconnect；组件不自行推断范围。
- `MemeState.NetworkLinked` 按所有来源汇总，`NetworkSourceCount`可读取来源数。离开一个节点不影响其他节点。
- 旧布尔赋值作为独立手动来源：true增加手动暴露，false只移除手动暴露。不得用false模拟节点退出。`ClearNetworkLinks()`显式解除全部来源。
- 节点组件或对象停用、销毁、显式DisconnectAll会双向释放自身连接。重新启用或重建后成员为空，须重新登记。
- 棋子死亡、Init/Reset、销毁双向移除旧成员；棋子临时隐藏不清理。死亡目标、停用节点、已结束或停用的战斗拒绝连接。
- BattleManager持有本场已连接节点，在初始化、胜负、退出及禁用入口清理；不使用跨战斗静态连接表。清理也撤销本场棋子的旧手动暴露，不增加恢复抗性。

### 跨类型边界

沿用既有MemeResolver及正式1001–1006目录的 `allowNetworkCrossType`。网络只放宽该词条允许的生物/机械目标门槛，保留正式身体类型和剧情标签。未配置身体不因网络补成生物或机械。

网络不会绕过剧情标签、显式识别、友敌关系、反应开关、触发时机、同次行动去重及抗性/免疫，不会自动施加任何状态。连接不收费、不掷骰，不写永久存档。断开网络仅取消后续跨类型资格，已施加状态继续按B10/B11计时、刷新、解除和恢复抗性规则处理。
