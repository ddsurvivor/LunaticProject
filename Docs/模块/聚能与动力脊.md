# 聚能与动力脊

当前实现仍按参与人数每人扣50、选人后顺序行动；额外AP不推进普通速度条、不重复普通回合开始/结束，退出恢复普通AP并进入3个普通棋子回合冷却。命中敌人及我方实际掉血充能，零掉血不计受伤充能；进行中不自充能。

**待实施的 B58 将改为一次统一扣50、三名主角自由切换并把速度条提前。该需求尚未实现，以[开发计划](../开发计划.md)的阶段要求为准。** 保留等待在途动作完成后接管的保护。

调度入口为 `BattleManager.BurstTurns.cs` 与 `BattleManager.SpeedTurns.cs`，容量和冷却由 `BurstGauge.cs` 管理，基础充能来自 `GameConst.attackBurstCharge/hurtBurstCharge`。旧说明中的范围/爆炸免疫提案已被取消；退出后爆炸正常结算。

## 延期结算

日期：2026-10-30。范围：B14、B15、B17、B29的现有棋子、爆炸物、聚能调度与PR4-2受控验收。

### 已确认规则

用户明确纠正“不是免疫伤害，而是那些爆炸伤害会在聚能结束后才结算。例如自爆的无人机、会爆炸的油桶”。因此B14改为伤害延期，没有任何范围/爆炸免疫。

聚能参与者的直接技能/攻击即时结算HP，直接范围攻击仍沿原技能规则。敌方或未参与者攻击、插件/碰撞派生伤害及无来源旧扣血入口延期；爆炸桶、自爆敌人、召唤自爆兵、电浆脉冲和死亡触发效果到退出后正常结算。参与者和未参与队友届时都可能受到伤害。

B10/B11已确认的普通回合DOT、付费行动散热伤害/麻痹及状态自伤保持原触发时机，不将这些规则改成延期或免疫。尚未正式定义的环境伤害不能仅根据伤害类型名称推断为直接攻击。

### 实现

- BattleManager.BurstDeferred持有本场触发顺序队列与可暂停引信。聚能开始将已有引信连同剩余时间移入队列，新触发效果追加；多人角色交接不释放。退出后逐项结算，连锁追加队尾，保留原行动根ID。
- PieceDisplay独立冻结受击/死亡首帧，不占用普通一次性播放锁，避免冻结画面阻塞聚能输入。直接伤害造成的HP变化立即提交；敌方受击、命中镜头、死亡事件、被动通知及击退/夹击/警戒等待释放。致死立即撤销棋子行动和模因状态。
- 普通桶、正式Enemy11无人机及电浆桶、SelfExploreSummonPiece、SelfRevive延迟入口使用战斗引信。爆炸目标按实际爆炸时的原范围查询，伤害与附加效果仍经过原PieceSkill/DamageManager，不补免疫或改概率、伤害数值。
- 爆炸物记录位置、Rigidbody、NavMeshAgent、Animator及原本播放中的粒子快照；聚能期间固定位置并暂停，结束或清理时归还。Init或停用先释放旧快照；重新启用在新位置重新登记。
- 死亡回收排到已触发爆炸之后，淡出也纳入表现等待。正常/提前结束都先释放再交还普通控制，胜负在冻结结果清空后提交。禁用、主动退出、卸载清空旧队列，不补发已取消关卡的效果。
- 每个事件校验Unity对象、启用状态、棋子Init版本和对象池租期；组件停用取消本组件引信。重建后的旧回调不能作用于新一轮对象。
- B17不再改共享材质。按渲染器保存引用并创建实例副本，AllIn1材质使用灰度关键字，其他材质使用主纹理/颜色/透明度灰度回退；运行中新增物件和粒子也纳入。选中者保留彩色，取消、退出与清理恢复原引用并销毁副本。Canvas界面沿用现有样式。

后续环境模块应调用 `ScheduleWorldEffect(owner, delay, actualCallback, action)` 或 `TryDeferBurstEffect(owner, actualCallback, action)`；回调传实际实现，避免再次进入同一排队入口。组件OnDisable调用CancelWorldEffects，并在拥有爆炸物物理快照时调用ReleaseExplosiveBody。直接伤害必须传真实BattleDamageSource，不能依赖Unknown绕过延期。

## 档案、关卡与升级

### 运行行为

- `PLAYERPROFILE.powerSpineProgress` 保存 `PowerSpineProgress.level`。旧档缺字段、字段为 null 或缺少档案时，战斗按零级初始化；负值按零级、超过三级按三级读取。新游戏重置设施进度。
- `PlayerController.Init` 在初始化事件之后读取当前档案，覆盖旧的 Inspector 调试等级。保留原 `powerSpineLevel` 序列化字段作为实际读取等级显示，不再作为正式进度来源。
- 普通关卡按已确认规则：等级 0/1/2/3 对应容量 100/130/160/200，充能倍率 1/1/1.1/1.21，每人费用仍为 50。入场或重开初始化时能量及冷却清零。
- `Assets/Resources/Battle/BurstStages.json` 是明确的场景规则目录，当前将 `PR0BATTLE` 绑定为 Prologue。未列出的场景默认 Normal，不再根据 `chapterNumber == 0` 猜测序章。普通关卡即使玩家章节为零，也能使用已升级设施。
- `PlayerController.burstStageKind` 可显式指定 Normal、Prologue、Tutorial；Unspecified 时读取目录。显式类型优先于目录，旧 `forceDefaultBurstCapacity` 标志始终强制基础规则。序章和教学同时限制容量与充能倍率，不改永久设施等级。

### 升级与保存接入

设施界面通过 `GM.TryUpgradePowerSpine(rules, expectedLevel, out error)` 校验解锁、费用与报价等级。无参 `GM.TryUpgradePowerSpine()` 现也读取正式 JSON 配置并校验费用，不再作为免费升级旁路。成功提升一级，三级返回 false；档案缺失、战斗会话、战斗运行或转场期间均拒绝升级。旧档的 null 进度在允许升级时建立。

接口不会猜测存档槽，也不自动写盘。成功后由正式设施界面按用户选定槽调用既有 `DataManager.SaveData(index)`；档案 JSON 已携带设施字段，战前 JSON 快照也自然包含它。低层 `PowerSpineProgress.TryUpgrade()` 仅负责等级规则，不负责业务限制、费用和写盘。

设施界面已使用用户授权的临时数值，费用与入口见下节；最终经济平衡仍待确认。

### 配置新关卡

1. 普通关无需添加目录项，保持 Unspecified 即读取永久等级。
2. 新序章或教学关在 `BurstStages.json` 增加精确场景名与类型值，或在该关 `PlayerController` 上显式配置类型。
3. 枚举值：Unspecified=0、Normal=1、Prologue=2、Tutorial=3。目录类型无效时按普通关处理；缺目录资源或空目录也按普通关处理。目录是只读资源，运行时不通过修改它来升级设施。
4. 不因某普通关存在操作提示面板就把它当作教学关；新教学关须明确标记。本轮只配置已确认的 PR0BATTLE，没有擅自修改其他关卡类型。

### 设施配置与玩家入口

采用用户授权的可调整临时配置，不作为最终经济平衡：

| 升级 | 金币费用 | 章节门槛 | 升级后容量 / 充能倍率 |
| --- | --- | --- | --- |
| 0→1 | 500 | 0，无章节限制 | 130 / ×1 |
| 1→2 | 1000 | 1 | 160 / ×1.1 |
| 2→3 | 2000 | 2 | 200 / ×1.21 |

- 配置：`Assets/Resources/Battle/PowerSpineUpgrades.json`。可逐级调整费用、章节、启用和剧情进度要求；本轮不要求剧情键。每人 50 入场费用及序章/教学基础能力保持既定规则。
- 战外侧栏底部显示“动力脊设施”，打开 `Resources/UI/PowerSpinePanel`；展示当前金币、等级、当前/下级能力与费用。先点击升级报价，再确认提交；取消不扣费，满级/金币不足/未解锁禁用按钮，确认时更换档案或等级变化均拒绝旧报价。
- 点击“打开存档”打开场景内已有存档页及必要父容器，沿用原存档位和关闭事件；不新增自动存档槽，不自动写盘。此前存档页嵌套在关闭的队伍窗口内，本轮修复设施入口仅开启子页而不可见的问题。
- 新模板沿用 AVG Panel/Header/Button 嵌套模块，编辑器菜单 `Tools/Facilities/Create Power Spine Templates If Missing` 仅创建缺失资源。面板、文字、按钮位置可直接手调，侧栏 `powerSpinePrefab` 可指定 Variant，生成器不覆盖已有资产。侧栏按钮是独立资源，可调整尺寸和底部位置。
- 非战斗场景创建入口，转场期间隐藏并禁止打开；避免在 `Start` 时转场尚未结束而永久漏建按钮。设施打开期间进入转场会自动关闭。

B16仍需真实存档槽保存重进、教学/普通关/重开完整流程及最终费用平衡；已实现界面不等于这些流程已验收。
