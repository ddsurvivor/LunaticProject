# 战斗系统开发计划与验收

更新：2026-10-29。用途：集中记录 LunaticProject 战斗系统的待开发、待修复、待验收和待确认事项，供后续按编号执行与持续更新。

结构参考：`E:/GameDev/ChessFrame/Docs/开发计划与验收.md`。仅借鉴功能汇总、编号待办、分批执行和证据记录方式；该项目的舰船规则、任务编号、交付日期及测试结论不适用于本项目。

本版依据本项目文档及部分代码入口整理，未进行完整代码审计、Unity 运行或构建。当前工作区存在战斗代码、UI、预制体和场景的未提交修改，执行前须复核现状；下文“文档已有”不代表本次验证通过。架构设计中的建议不自动成为已确认需求。

## 1. 状态与维护约定

| 状态 | 使用条件 |
| --- | --- |
| 待核对 | 文档与当前代码可能不同，需先定位实现和实际入口 |
| 待确认 | 规则或交付范围未定，先记录决策，再开发相关行为 |
| 待开发 | 已有资料明确列出缺口，执行前仍检查是否已有新实现 |
| 待修复 | 有具体问题记录，需在当前版本复现 |
| 待验收 | 已有实现或历史证据，缺少当前版本的对应验收 |
| 进行中 / 受阻 / 暂缓 | 记录当前步骤、阻塞原因或恢复条件，不算完成 |
| 完成 | 实现与本项约定验收均完成，附日期、版本范围与证据 |

- 编号永久保留，新增事项从最大编号继续，不因排序变化重编号。
- 一轮优先执行一个编号；发现独立问题另建编号，不无限扩大当前任务。
- 每项执行“核对现状 → 最小修改 → 定向验证 → 更新记录”。已有能力优先补验，不重复开发。
- 实现、静态检查、规则测试、Play Mode、视觉与构建分别记录；未执行写“未执行”。历史通过不能替代当前版本通过。
- 优先级是建议顺序：P0 为基础链路/阻塞项，P1 为主要功能，P2 为增强与整理，不表示已承诺排期。
- 遵循根目录 [AGENTS.md](../AGENTS.md) 与 [代码注释规范](代码注释规范.md)。临时测试脚本、替身、资源和生成结果放根目录 `tmp/`，不得加入 Git；`Assets/BattleTesting/` 仅保留规则允许的运行时自动战斗模块及必要资源、入口。报告与截图仍放 `tmp/`。
- 文档保留结论及复现步骤；临时证据可能被清理，不将其作为唯一的长期说明。文档修改检查内容与链接，业务修改再做对应编译与定向验证。
