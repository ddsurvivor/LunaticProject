# 方尖碑光环与 B37 验收

2026-11-05，`dev_feature`。用户明确采用本轮提出的规则，B37 按以下口径实现；B38 群体护盾另行处理。

## 确认规则与接入

- 方尖碑 `Enemy10.prefab` 增加 `ObeliskAura`，默认球形半径8、治疗比例35%，可在 Inspector 手调，选中时显示范围Gizmo。目标使用已有 `memeTargetTags` 的“黑衣人”标签，不另建阵营标签字段。
- 在目标普通回合开始时治疗自身最大生命35%，向上取整、截断到生命上限，包含方尖碑自身，仅作用于当前关系中的友方黑衣人。采用现有 `BattleRelations.CanSupport`，不会改变原始胜负阵营。
- 2026-11-06补充破盾停机：来源停机的两个自身普通回合内，治疗光环暂停；停机结束自动恢复范围及关系判定。
- 多个光环不叠加；若手调强度不同，取最强，强度相同按参战注册顺序取首个。来源失活、死亡、禁用、销毁或目标越界便失效，没有残留Buff需要移除。原 AutoHeal 保持原逻辑，独立结算。
- 时序为原回合开始事件 → 旧Buff → 光环治疗 → 本回合快照内细胞自毁 → 开放行动。旧Buff已致死时不复活；聚能额外行动不调用普通回合入口。重复查询同一个普通回合不重复治疗；初始化、回合结束及战斗清理均清除本次结算标记。
- 治疗直接使用现有 `UnitAttrCenter.Heal`，保留已有表现、通知和生命上限；当前该入口没有另行的减疗乘数。本轮不改旧治疗公式，也不把35%当作 AutoHeal 层数。

## 逆转敌我永久免疫

`PieceData.permanentMemeImmunities` 保存固有免疫，方尖碑配置1005。`MemeService` 将永久配置与本场临时抗性分开读取，永久免疫不被状态解除、Init或重开清空；其他棋子默认空列表，沿用原行为。

预览和实际提交都使用原词条门槛与免疫判定，满足其余门槛时返回 Immune、概率0，不掷随机数。未通过识别等门槛时仍报告相应门槛失败。共享状态读模型显示永久免疫及当前治疗光环，UI和AI使用同一份目标状态。

## 屠龙术一次传播

根目标仍先走原1006词条15%成功率和门槛。预览只读，不杀人、不治疗、不传播。成功作用于方尖碑时：

1. 快照本场有效参战者中半径8内所有黑衣人及生命版本，包含不同阵营，排除来源自身；使用 `SpeedParticipants` 的稳定注册顺序。
2. 立即清空方尖碑当前生命，沿原死亡入口执行事件和动画；聚能期间逻辑死亡立即生效，死亡表现沿现有队列延期。
3. 按快照传播已成功的词条效果，不再次投15%施加率。完全免疫仍阻止效果；这是一次成功效果的传播，不对次级目标再投临时部分抗性。普通黑衣人沿原4普通回合禁攻状态、解除与恢复抗性逻辑；其他方尖碑同样秒杀，但不再扩散自己的范围。
4. 死亡事件导致目标移动时仍按命中范围快照传播；已经死亡、离场或重新初始化的旧生命不承接效果，防止死亡链和对象池旧回调污染。

根死亡、屠龙术传播及普通状态不新增第二套伤害或AI控制器。没有新建隐藏攻击、普通命中或额外反应。屠龙术正式说明增加方尖碑特例，其余词条配置不变。

## 配置与范围

`Tools > Battle > Obelisk > Apply Confirmed Support Configuration` 为已有正式方尖碑补入光环及1005免疫；已有光环参数不覆盖，重复执行不叠加组件或列表项。正式数据仍在 `PieceDataListSO`，组件参数在 `Enemy10.prefab`，从而覆盖已有PR4-2中的连接实例；不改已停用草稿或其余敌人prefab。

此项不扩展用户已跳过的面板迁移，不实现群体护盾。临时验收脚本、场景内测试单位及结果位于根目录 `tmp/ObeliskImmunity/`、`tmp/ObeliskSupport/`，不加入Git。
